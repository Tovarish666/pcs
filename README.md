# PCS — Proxy Control Service v4

Прокси ген1 (`host:port:login:pass` от настоящего модема) превращается в **виртуальный модем**: сервер видит воткнутый в USB Huawei E3372h (HiLink, `12d1:14dc`, `cdc_ether`), берёт у него по DHCP `192.168.N.100`, ходит через него в интернет, а на `192.168.N.1` отвечает веб-морда настоящего модема (смена IP, перезагрузка, статус). Такой модем отдаётся агрегатору (mobileproxy.space и любому, кто работает с USB-модемами) или прямо клиенту — прокси на каждый модем.

**Отдельных ВМ под модемы нет.** Каждый модем — network namespace на самом сервере; 40 модемов поднимаются меньше чем за минуту и занимают около 1,5 ГБ памяти.

```
Google-таблица: n, real, proxy
        │  vmodem sync — при загрузке и каждые 2 минуты
        ▼
Сервер Ubuntu 24.04 (ВМ Proxmox или железо)
 ├─ netns vm201: usb0 192.168.201.1 · DHCP ровно .100 · DNS · веб-морда · туннель → SOCKS5 ген1
 ├─ netns vm202: …                                     │ USB: dummy_hcd (в ядре, без сети)
 │                                                     ▼
 └─ сам сервер:  eth1 cdc_ether 192.168.201.100  ◄─ «Huawei E3372» в lsusb
                 └─ mobileproxy.space / свой DHCP и маршруты / прямые прокси :20201
```

## Установка

На хосте Proxmox:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Tovarish666/pcs/main/install.sh)
```

Появится команда `pcs` (без аргументов — меню). На обычном сервере Ubuntu та же команда поставит только агент `vmodem` — модемы работают и без Proxmox.

## Весь путь одной командой

```bash
pcs server create --sheet 'https://docs.google.com/spreadsheets/d/ID/edit#gid=0' --mpspace
```

1. **ОС.** ВМ из облачного образа Ubuntu 24.04 (сумма проверяется): `apt upgrade`, ядро с модулями USB-гаджетов, заголовки для dkms, root по паролю и ключ PCS, sshd, предсказуемый DNS, авто-обновления выключены, перезагрузка на новое ядро.
2. **Агент** `vmodem`: собирает `dummy_hcd` под это ядро (dkms — переживёт обновления), ставит sing-box (сумма проверяется), службы и таймер.
3. **Модемы** по таблице.
4. **Софт** mobileproxy.space: зеркала, при необходимости HTTP-прокси, `auth.mp`, их скрипты, перезагрузка. В конце — сводка для ЛК.

Параметры: `--id --name --cores --ram --disk --storage --bridge --ip 192.168.1.60/24 --gw --dhcp --dns --password` (лучше через `PCS_PASSWORD`), `--auth '<json>'`, `--proxy http://…`. Чего не передали — спросит.

Существующую ВМ — под управление: `pcs server adopt VMID` (ключ кладётся по паролю один раз).

## Таблица

| n | real | proxy | enabled |
|---|---|---|---|
| 201 | 81 | 188.134.95.184:1198:modem81:пароль | |

- **n** — номер модема для сервера: модем `192.168.n.1`, сервер получает `192.168.n.100`.
- **real** — октет настоящего модема за прокси (`81`, `192.168.81.1` или `192.168.81.100`).
- **proxy** — `host:port:login:pass` (или колонки `proxy_host`, `proxy_port`, `login`, `password`).
- **enabled** — необязательная; `0` — модем снять, строку оставить.

Ссылку можно давать прямо из адресной строки; таблица должна быть доступна по ссылке.

## Команды

На хосте Proxmox (`--server VMID` — не активный сервер):

| команда | что делает |
|---|---|
| `pcs` | меню |
| `pcs status` | все серверы: ВМ, агент, модемы ✓ ⚠ ✗, чей софт |
| `pcs server create / adopt / list / use / info / update / delete` | серверы |
| `pcs m <команда vmodem>` | модемы сервера (всё из таблицы ниже) |
| `pcs mpspace install / auth '<json>' / check` | mobileproxy.space |
| `pcs soft run <url>` | свой софт установочным скриптом |
| `pcs dns`, `pcs passwd`, `pcs ssh`, `pcs exec 'cmd'` | обслуживание |
| `pcs update` | обновить PCS и агентов |

На сервере (`vmodem …` или `pcs m …` с хоста):

| команда | что делает |
|---|---|
| `vmodem source <ссылка>` | задать таблицу (проверит перед тем, как запомнить) |
| `vmodem lint` | проверить таблицу, ничего не трогая |
| `vmodem sync` | привести модемы к таблице (таймер делает это сам) |
| `vmodem status [--fast] [--json]` / `vmodem watch` | состояние: USB, адрес у сервера, внешний IP, диагноз |
| `vmodem diag N [--udp]` | цепочка прокси → логин → модем → SIM → интернет |
| `vmodem rotate N` | сменить IP (как mp.space для типа 3) и дождаться смены |
| `vmodem reboot N` | перезагрузить настоящий модем; USB пропадает, пока тот не вернётся |
| `vmodem replug N`, `up N`, `down N`, `logs N` | один модем |
| `vmodem proxy on [--base-port 20000]` | прямые прокси: SOCKS5+HTTP на `base+N`, выход через модем |
| `vmodem notify telegram TOKEN CHAT` / `webhook URL` / `test` | оповещения об изменениях |
| `vmodem dns-fix` | DNS сервера в порядок |

## Насколько модем похож на настоящий

- USB: `12d1:14dc`, строки `HUAWEI_MOBILE`, функция ECM → драйвер `cdc_ether`, MAC со стороны сервера `0c:5b:8f:27:9a:64` (у всех E3372h один).
- Вставляется, когда уже готов: DHCP модема слушает до появления на шине.
- DHCP: шлюз и DNS — сам модем, аренда сутки, адрес ровно `.100`.
- DNS на `192.168.N.1` — DNS настоящего модема (по TCP через прокси: UDP у прокси ген1 не работает).
- Веб-морда `192.168.N.1`: HiLink настоящего модема, адреса в ответах переписаны на виртуальные. Опасные записи (подсеть DHCP, пароль, прошивка, сброс) не проходят, обходы фильтра (`http://…`, `//`, `%xx`, регистр) закрыты. SMS не закрыты — их закрывает mobilink на ген2.
- Перезагрузка через веб-морду (Control=1): USB пропадает и возвращается, когда настоящий модем снова отвечает — как у живого.
- USB reset со стороны сервера (как делает mp.space) — работает.

## Если что-то сломалось

Своя сторона чинится сама, чужая — только диагноз и предупреждение.

| что | что происходит |
|---|---|
| упал процесс модема | systemd поднимает за секунды, маршруты туннеля восстанавливаются |
| сломалась сеть модема, пропал netns | `sync` пересоздаёт модем (≈6 с) |
| сервер не взял адрес | переподключить USB → если не помогло, пересоздать |
| не привязался слот USB | взять другой слот; 3 неудачи подряд — пауза 10 минут |
| прокси мёртв, неверный пароль, SIM не оплачена, нет связи | модем **создаётся и ждёт**; `status` и оповещение говорят, в чём дело |
| таблица недоступна / пустая | берётся последняя удачная |
| таблица вдруг требует снести больше половины модемов | не сносит без `--force` |
| кривая строка про работающий модем | модем не трогается |
| один n дважды; n и n+200; 153–155; n = сеть сервера | строки не берутся, причина названа |
| перезагрузка сервера | таймер поднимает все модемы через ~15 с после старта |

Диагнозы: `proxy-down` · `proxy-error` · `proxy-auth` · `modem-blocked` · `modem-unreachable` · `sim` · `no-data` · `captive` (SIM не оплачена) · `no-internet`. Интернет проверяется двумя целями с повтором, а оповещение о поломке уходит, только когда она подтвердилась двумя проверками подряд (о восстановлении — сразу).

## Проверено на стенде

Proxmox VE 9.1, ВМ Ubuntu 24.04 (ядро 6.8.0-142), прокси ген1 на 20 модемов.

| что | результат |
|---|---|
| `pcs server create` с нуля (образ → ОС → агент) | 5–6,5 мин, из них cloud-init с `apt upgrade` 3–4 мин |
| `pcs server adopt` существующей ВМ с модемами | ~1 мин |
| `pcs mpspace install` | ~6 мин вместе с перезагрузкой; после неё mp.space сам подхватил все модемы |
| 20 модемов по таблице | 28–40 с; 40 модемов — ~50 с (окно 5); ~1,5 ГБ памяти на 40 |
| перезагрузка сервера | модемы и прямые прокси снова работают через ~45 с |
| смена IP (`rotate`) | ~10 с |
| перезагрузка через веб-морду (как делает mp.space) | USB пропал через 3 с, вернулся через 26 с — когда настоящий модем загрузился |
| USB reset кодом mp.space | работает |
| mp.space `modem-manager status` | «Активных модемов: 20, Curl ✓ 20 / ✗ 0» |

## Грабли, которые PCS обходит сам

- **У всех E3372h один MAC** — Ubuntu называет USB-сетевуху по MAC (`enx…`), второму модему имя не достаётся, и udev бросает его недонастроенным. PCS оставляет ядерные имена `ethN` (как mobileproxy.space).
- **`systemd-networkd` при перезапуске стирает чужие `ip rule`** — то есть маршрутизацию всех модемов (при любом `netplan apply`). PCS запрещает ему это; если правило всё же пропало — `sync` заметит и восстановит.
- **dnsmasq иногда не подхватывает интерфейс модема** — проверяется и перезапускается; mp.space повторять DHCP не умеет.
- **Падение туннеля стирает его маршруты** — они возвращаются при каждом перезапуске.
- **Выгрузка `dummy_hcd` при живом гаджете ломает ядро до перезагрузки** — разборка всегда сверху вниз; не привязавшийся слот обходится.
- **UDP через прокси ген1 не работает**: UDP ASSOCIATE принимается, но порт ретранслятора на сервере прокси закрыт (ICMP port unreachable) — это чинится на стороне прокси. Поэтому DNS модема ходит по TCP. `vmodem diag N --udp` покажет, заработал ли UDP.

## Устройство

```
pcs                 хост Proxmox: серверы, меню, управление (python3)
agent/vmodem        сервер: модемы, диагностика, свой DHCP, прямые прокси, mp.space (python3)
agent/vmodem-api    веб-морда модема на виртуальном адресе
tests/              проверки без root и без ВМ: bash tests/run-all.sh
tests/stand/        стендовые сценарии: отказы, стратегии создания, поддельный SOCKS
```

Модем `N` на сервере: netns `vmN`, гаджет configfs `vmN` на `dummy_udc.K`, службы `vmodem-{dns,sb,api}@N`. Настройки — `/etc/vmodem/config.json`, состояние — `/var/lib/vmodem`, журнал — `/var/log/vmodem`. На хосте — `/etc/pcs` (права 600).

Ограничение ядра: у каждого модема своя USB-шина, а шин не больше 63 — на одном сервере до ~55 модемов.
