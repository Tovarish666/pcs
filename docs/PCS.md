# PCS 5 — полная документация

Документ описывает PCS 5 целиком: зачем он, как устроен, все команды, файлы, форматы,
HTTP API, решения и грабли. Его можно отдать новому чату или новому разработчику, и тот
войдёт в контекст без пересказа.

Короткий контракт между частями — `docs/ARCHITECTURE.md`. Этот файл шире и подробнее.

---

## 0. Коротко — для нового чата

- **Что это.** Софт для фермы мобильных прокси. Купленная прокси «ген1»
  (`host:port:login:pass` — SOCKS5 от настоящего модема) превращается в
  **виртуальный модем**. Агрегатор mobileproxy.space (mp.space) или свой софт видит его
  как настоящий USB-модем Huawei E3372h HiLink. Обратное направление — из любого
  интерфейса сделать прокси с логином и паролем для клиента.
- **Где живёт.** PCS ставится одним `install.sh` на два вида машин — «хосты»:
  - **хост Proxmox VE** (Debian): хаб `pcs` создаёт на нём ВМ Ubuntu 24.04 — «серверы»;
  - **хост Ubuntu 24.04+ (VPS у хостера)**: ВМ нет, модемы и софт — прямо на нём (§5).

  Хосты связываются между собой по API (§19): на хосте Proxmox «+ Присоединить хост» →
  адрес, логин и пароль панели VPS. На серверах и хостах работают части:
  - `proxyveth` — прокси → интерфейс;
  - `modlink` — интерфейс → прокси;
  - `hivelink` — драйвер настоящих модемов (на хосте стоит всегда, в ВМ — по запросу).

  На самом хосте стоят `hivelink` и `modlink`: настоящие модемы, воткнутые в хост, сразу
  становятся прокси, а из них — виртуальные модемы в ВМ этого же хоста (§9.6).
- **Как управлять.** Терминал (команды и меню `pcs`) и веб-панель на порту 666.
- **Состояние на 12.10.2026.** Всё в `main`; проверенное на стенде вливается сразу.
  - Проверено на стенде: установка на хост Proxmox и на Ubuntu-VPS (ВМ 4000 как VPS),
    создание ВМ в обоих режимах, переезд со старого vmodem 4.1, трафик, DNS, modlink
    (защита, перенос с modlink-linux), hivelink, фоновые задания при обрыве связи,
    присоединение VPS к хосту Proxmox и работа с ней через хаб.
  - Тесты: около 1160 проверок, все зелёные (`bash tests/run-all.sh`).
- **Отложено по решению пользователя:** yaspeed (спидтест), оповещения в Telegram (код
  есть, в меню и панели нет).

## 1. Легенда

Всё началось с ProxyControlService — bash-скрипта. Он поднимал на Proxmox ВМ под
mobileproxy.space и превращал купленные прокси в «модемы», которые агрегатор принимал за
настоящие.

Ферма росла, и вокруг появлялись инструменты, каждый под свою задачу:
- proxyveth делал из прокси сетевые интерфейсы;
- proxyveth-virt развязал виртуальный и реальный номер модема;
- vmodem маскировал интерфейсы под USB-модемы Huawei;
- modlink раздавал прокси с модемов;
- hivelink (e3372-driver) оживлял настоящие модемы.

Каждый жил отдельно — свой установщик, свои версии sing-box — и иногда они ломали друг
друга.

PCS 5 собрал их в одну семью с одним пультом, одной версией зависимостей и одной схемой
маршрутизации:

| часть | одной фразой |
|---|---|
| **pcs** | пульт и хаб: создать сервер, поставить софт, DNS, доступы, обновить, показать состояние |
| **proxyveth** | из прокси — сетевой интерфейс; режимы `usb` (как USB-модем, до ~40 на сервер) и `gw` (шлюз без USB, без такого предела) |
| **modlink** | из интерфейса — прокси (HTTP и SOCKS5 с логином), смена IP по ссылке и таймеру |
| **hivelink** | драйвер настоящих модемов Huawei/Vodafone |

Два пути трафика:
- прокси ген1 → proxyveth → интерфейс 192.168.N.100 → mp.space или modlink → клиент;
- настоящий модем → hivelink → интерфейс → modlink или mp.space → клиент.

## 2. Термины

| слово | значение |
|---|---|
| хост | машина с Proxmox VE (Debian 12/13), где живёт хаб `pcs` |
| сервер | ВМ Ubuntu 24.04 под модемы. Одна ВМ — один сервер. В API — номер ВМ (`id`) |
| `host` | в API и командах — сам хост, в отличие от сервера |
| модем N | номер 1–254. Модем — 192.168.N.1, сервер получает 192.168.N.100 |
| real | октет настоящего модема за прокси (192.168.real.1 у его мини-сервера). Пусто — real = n |
| прокси ген1 | `host:port:login:pass`, SOCKS5 к сети настоящего модема (за ней 192.168.real.1) |
| ген2, ген3 | прокси для клиентов и агрегаторов (на балансировщике) и прокси, выдаваемая клиенту. Не часть PCS |
| mp.space | mobileproxy.space — агрегатор; его софт ставится на сервер (`pcs mpspace install`) |
| режим usb | proxyveth: модем — USB-гаджет (бывший vmodem) |
| режим gw | proxyveth: модем — veth-шлюз без USB (бывший proxyveth-virt) |
| HiLink | веб-API настоящего модема Huawei на 192.168.x.1 |
| часть | proxyveth, modlink или hivelink — то, что работает на сервере (или хосте) |

## 3. Общая схема

```
Google-таблица: n, real, proxy          хост Proxmox (Debian)
        │                               ├─ pcs (хаб), меню, /etc/pcs
        │                               ├─ веб-панель :666 (pcs-web.service)
        │                               ├─ hivelink (настоящие модемы на USB хоста)
        ▼                               └─ ВМ ───────────────────────────────┐
ВМ Ubuntu 24.04 (сервер)                                                      │
 ├─ proxyveth   режим usb:  netns pvN ─ usb0 192.168.N.1 ─ USB-гаджет «Huawei E3372h»
 │                          (dnsmasq DHCP .100, DNS, sing-box tun → сокет → SOCKS5 ген1)
 │              режим gw:   netns pvN ─ veth pvN 192.168.N.100 ↔ eth0 .254 (sing-box tun → SOCKS5)
 ├─ сторона сервера: ethN (usb) или pvN (gw) с адресом 192.168.N.100
 │   └─ mobileproxy.space / свой DHCP и маршруты
 ├─ modlink     0.0.0.0:порт (HTTP+SOCKS5, логин) → выход с адреса lan_ip (любого интерфейса)
 └─ hivelink    по запросу (настоящие модемы, проброшенные в ВМ)
```

**Тесты.**
- `bash tests/run-all.sh` — без root, без ВМ, без сети. Исключение — однократное
  скачивание sing-box для `sing-box check`; без сети эти проверки пропускаются.
- Каждый `tests/test_*.py` печатает «итого: ok N, fail M» и возвращает код 0/1.
- Конфиги sing-box проверяются настоящим `sing-box check` той же версии, что ставится
  на серверы (`tests/singbox_check.py`). Предупреждение `deprecated` — тоже провал.
- `tests/stand/` — сценарии для живого сервера: нагрузка, отказы, стратегии создания.
  Остались от PCS 4 и местами ссылаются на старые имена.

**Стиль.**
- Только стандартная библиотека Python: 3.12 на серверах, 3.11+ на хосте.
- Сообщения — по-русски, коротко: что случилось и что делать.
- Ошибка — одна строка `✗ …` в stderr и код 1, без трасс.

## 5. Установка и обновление

### Хост — Proxmox или Ubuntu (VPS)

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Tovarish666/pcs/main/install.sh)
```

**Требования:** root, Python 3.11+ и одно из двух:
- **Proxmox VE** (`qm`, `pvesm`, `/etc/pve`) — хост с ВМ;
- **Ubuntu 24.04 или новее** — хост-VPS: модемы и софт прямо на нём, ВМ не создаются.

Другие системы — понятный отказ.

**Что делает `install.sh`:**
1. Скачивает `PCS_REPO@PCS_BRANCH` (по умолчанию `Tovarish666/pcs@main`) или берёт
   готовое дерево из `PCS_SRC=/путь`.
2. Проверяет, что код компилируется. Кладёт его в `/opt/pcs`, прежний — в `/opt/pcs.prev`
   (откат — переименовать обратно). Пишет `/opt/pcs/.source` (`PCS_REPO`, `PCS_BRANCH`):
   отсюда же берёт код `pcs update`.
3. Ставит команды `/usr/local/bin/{pcs,proxyveth,modlink,hivelink,pcs-node}`.
4. Спрашивает логин и пароль панели (или берёт `PCS_WEB_USER`, `PCS_WEB_PASS`), сохраняет
   хэшем и включает `pcs-web.service` на порту 666. Если вход уже задан — не спрашивает,
   но панель всё равно включает (`pcs web on`).
5. Дальше — `pcs host-setup` (его же зовёт `pcs update --host`):
   - ссылки `/usr/local/bin/{pcs,hivelink,modlink}`;
   - hivelink на хост (`hivelink install`). Первая установка тяжёлая: ставятся
     `proxmox-headers-*`, `build-essential`, `dkms`, собирается модуль — несколько минут;
   - modlink на хост (`modlink setup`: 3proxy 1.0.0, юниты `modlink` и `modlink-3proxy`; прежний
     `modlink-sb` с sing-box снимается). Строк нет — 3proxy стоит, демон работает. Если на хосте старый modlink-linux —
     его не трогает и подсказывает перенос (§9.6);
   - перезапуск панели, если она включена.

   **`pcs update --host` выполняет `pcs host-setup` уже новым кодом.** Раньше шаги после
   обновления шли из прежней версии: так PCS без modlink на хосте обновился в PCS с ним,
   а modlink не поставил (случай megavolgadata, 10.10).

**На Ubuntu (VPS) по-другому:**
- до долгих шагов спрашивает режим proxyveth (`usb` — для mp.space, по умолчанию; `gw`)
  и нужен ли mobileproxy.space (+ auth.mp). Без вопросов: `PCS_MODE=usb|gw`,
  `PCS_MPSPACE=1`, `PCS_MP_AUTH='{…}'`;
- `pcs host-setup --mode …`: proxyveth (сам ставит dnsmasq-base, udhcpc,
  linux-modules-extra, собирает dummy_hcd через dkms), modlink; hivelink — только если уже
  стоит (у VPS обычно нет USB-модемов; поставить: настройка хоста → hivelink);
- mp.space (если выбран) — заданием, в конце машина перезагрузится;
- в конце — адрес панели; если включён ufw — подсказка `ufw allow 666/tcp`.

Проверено 12.10.2026 на чистой Ubuntu 24.04.5 (ВМ 4000 стенда как VPS): установка с
`PCS_MODE=usb`, модем 41 из прокси modem8 поднялся (USB, внешний IP оператора).

### Серверы

- Код на сервер кладёт хаб: `/opt/pcs` (tar без `.git` и тестов) и ссылки
  `/usr/local/bin/{proxyveth,modlink,hivelink,pcs-node}`.
- `pcs update`:
  - без флагов — хост из GitHub, потом все серверы;
  - `--host` — только хост;
  - `--server ID` — только этот сервер;
  - `--all` — все серверы.
- На сервере после доставки кода:
  - `proxyveth setup` — без выбранного режима ничего не делает и только подсказывает;
    со старым vmodem 4.x сам переезжает;
  - затем `modlink setup`.
- **Версия кода одна** на хосте и всех серверах: `pcs/__init__.py: VERSION`.
  Сейчас `5.0.0-dev`.

## 6. Хаб `pcs` (хост)

### Команды

```
pcs                                   меню
pcs status [--json]                   хост и все серверы сразу
pcs server list | info [ID] [--password] | use ID|host
pcs server create [--mode usb|gw] [--sheet URL] [--mpspace] [--id N] [--name …]
                  [--ip A.B.C.D/M --gw …|--dhcp] [--cores N] [--ram ГБ] [--disk ГБ]
                  [--storage …] [--bridge vmbr0] [--dns "…"] [--replace] [--yes]
pcs server adopt ID [--ip IP] | delete ID [--yes]   добавить в PCS ВМ, что уже есть в Proxmox / удалить с дисками
pcs server start|shutdown|reboot|stop ID           питание ВМ (shutdown — штатно до 2 мин, stop — жёстко)
pcs server forget ID [--yes]          убрать из PCS: ВМ, диски и модемы не трогаются (так чистят ВМ,
                                      удалённые мимо PCS — в списке они «нет в Proxmox»)
pcs server color ID [цвет]            красный, оранжевый, жёлтый, зелёный, голубой, синий, фиолетовый; пусто — по номеру
pcs proxyveth …  [--server ID|--host] команда proxyveth на сервере или самом хосте (как есть)
pcs modlink …    [--server ID|--host]
pcs hivelink …   [--server ID|--host]
pcs dns     [--server ID|--host] [--dns "1.1.1.1 8.8.8.8"]
pcs passwd  [--server ID|--host]      пароль root (Enter — сгенерировать)
pcs key     [--server ID|--host] [--add PUBKEY | --rotate]
pcs ssh [ID] | pcs exec [ID] 'cmd'    консоль / команда на сервере
pcs ssh-port PORT [--server ID]       порт SSH сервера (на 24.04 — через ssh.socket)
pcs mpspace install|auth|check [--server ID|--host]   на хост — только Ubuntu (VPS)
pcs update [--host | --server ID | --all]
pcs web on|off|status|passwd|serve    веб-панель :666
pcs doctor [--server ID|--host] | pcs log | pcs version
pcs job [ID] [--server ID]            фоновые задания и запуски (§7.1): список, журнал, смотреть до конца
pcs host-setup [--mode usb|gw]        хост после установки/обновления: команды и части
pcs node [list|add АДРЕС|remove ИМЯ|open ИМЯ]   присоединённые хосты (§19): pcs node help
pcs node ИМЯ proxyveth|modlink|hivelink …       команда части на том хосте
pcs token [list|revoke ID]            кто присоединил этот хост (токены хабов)
```

- Без `--server` команда идёт на **выбранный сервер** (`pcs server use ID`; хранится в
  `/etc/pcs/active`). Если выбранного сервера больше нет (удалён мимо PCS, остался от
  прежней версии), он считается невыбранным. `pcs modlink` и `pcs hivelink` без
  выбранного сервера идут на хост.
- `--json` — ответ для программ (конверт, §7).
- **Секреты — не в командной строке:**
  - пароль root — `PCS_PASSWORD` или вопрос;
  - auth.mp — `PCS_MP_AUTH` или stdin;
  - HTTP-прокси для зеркал mp.space — `PCS_MP_PROXY`.

### Хранилище хаба — `/etc/pcs` (700)

| файл | что |
|---|---|
| `servers/<id>.json` (600) | сервер: `id`, `name`, `ip`, `net` (dhcp/static), `mode`, `created`, `pcs` (версия), `version`, порт SSH и др. |
| `active` | номер выбранного сервера (или `host`) |
| `ssh/id_ed25519`, `ssh/known_hosts` | ключ PCS для root на серверах, свой known_hosts. Ключ ВМ сменился («Host key verification failed») — новый сверяется через guest agent Proxmox (`qm guest exec … cat /etc/ssh/ssh_host_*_key.pub`) и, если совпал с тем, что ВМ показывает по сети, принимается сам; не совпал или сверить нечем — `pcs server trust-key ID --accept SHA256:…` (в панели: «управление» → «Ключ SSH сервера») |
| `web.json` (600) | вход в панель (§13) |
| `/var/lib/pcs/jobs/` | фоновые задания (§14) |
| `/var/log/pcs/` | журналы хаба |

### Создание сервера (`pcs server create`)

1. Образ Ubuntu 24.04 (cloud image) в `/var/lib/vz/template/iso/ubuntu-24.04-noble.img`.
   Сумма сверяется; если upstream обновил образ — скачивается заново.
2. `qm create` — и сразу запись сервера в `/etc/pcs/servers/<id>.json` (с 23.10.2026; раньше —
   только когда известен адрес): что бы ни упало дальше, ВМ остаётся в PCS — её можно удалить
   или «Повторить» создание, а не «добавлять в PCS» (adopt).
   - q35, `cpu host`, balloon 0, `onboot 1`;
   - virtio-scsi-single, диск с discard/ssd/iothread;
   - qemu-guest-agent, `serial0 socket`;
   - `tablet 0` — без «QEMU Tablet» в `lsusb`, по нему видно виртуалку;
   - сеть `virtio,bridge=vmbr0`.
3. cloud-init (свой user-data в `local:snippets/pcs-<id>.yaml`):
   - пакеты, `apt upgrade`; для режима usb — ядро с модулями USB-гаджетов
     (`linux-image-extra-virtual`) и заголовки для dkms;
   - root по паролю и ключ PCS;
   - sshd drop-in **`10-pcs.conf`**, а не `99-`: sshd берёт первое значение, а образ
     кладёт `60-cloudimg` с `PasswordAuthentication no`;
   - авто-обновления выключены, предсказуемый DNS.
4. Адрес ВМ:
   - через guest agent;
   - пока его нет — по SSH через IPv6 link-local (адрес выводится из MAC).
5. Ждёт `cloud-init status --wait`; если нужно новое ядро — перезагрузка.
6. Доставка кода. Затем DNS-фикс (`pcs-node dns-fix`).
7. `proxyveth mode <usb|gw> --yes` — он же готовит сервер. Не прошёл (например, не
   собрался `dummy_hcd` под новое ядро) — ВМ доделывается без него, таблица не ставится, в
   итоге задания — «Готово … — с замечаниями» и команда для повтора. ВМ на настоящих
   модемах proxyveth не нужен, но остаётся наготове.
8. `modlink setup`, затем **cloud-init выключается** (`/etc/cloud/cloud-init.disabled`, только у
   ВМ со сниппетом `pcs-<id>.yaml`; так же при «Обновить агентов»): своё он сделал, а включённый
   он перенастроил бы ВМ, когда Proxmox пересчитает instance-id (§17, п. 19).
9. Если задана таблица — `proxyveth source <ссылка>` и `proxyveth sync`.
10. Если задан `--mpspace` — `pcs mpspace install`: зеркала, при необходимости HTTP-прокси,
    `auth.mp`, их скрипты, перезагрузка ВМ, повтор DNS-фикса.

Создание из панели — то же самое, но фоновым заданием.

### Остальные операции

- **`adopt ID`** — взять под PCS существующую ВМ: ключ кладётся по паролю один раз.
- **`delete ID`** — с подтверждением номером: `qm stop` + `destroy --purge`, чистка `/etc/pcs`.
- **`dns`** — §11.4. На хосте — тоже: его DNS не должен ломаться от модемов.
- **`passwd`** — `chpasswd` со stdin на сервере. Для ВМ ещё `qm set --cipassword`.
- **`key --add PUBKEY`** — добавить свой ключ root. **`--rotate`** — перевыпустить ключ PCS.
- **`server trust-key ID [--accept SHA256:…]`** — ключ SSH сервера: что знает хаб, что сервер
  показывает, что видит guest agent; сменился и агент подтверждает — принять; без агента — только
  отпечаток, сверенный человеком в консоли ВМ.
- **«Связь» (панель, кнопка в шапке ВМ; с 23.10.2026)** — связь хаба с ВМ по шагам, чтобы после
  перезагрузки ВМ не ждать у моря погоды: ВМ в Proxmox (выключена — сразу так и сказано) →
  guest agent → адрес (у Proxmox: агент, соседи; сменился — записать) → порт SSH (молчит, а агент
  жив — `systemctl restart ssh` через агент) → вход (ключ сменился — сверка агентом). Окно —
  «Проверить ещё раз» и «Консоль ВМ».
- **Адрес сменился сам** (DHCP после перезагрузки): команда хаба получила «No route to host» /
  таймаут / отказ — хаб спрашивает у Proxmox текущий адрес ВМ, другой — записывает и повторяет
  команду (не чаще раза в минуту на ВМ). На стенде: в записи ВМ 2000 чужой адрес — `pcs exec`
  нашёл верный и прошёл за 8 с.
- **Консоль ВМ без сети и SSH** — терминал панели, кнопка «Консоль ВМ»: последовательный порт
  через Proxmox (`qm terminal ID`, у ВМ PCS есть `serial0`); вход — root и пароль, выход — Ctrl+O.
  WebSocket — тот же `/ws/term`, с `&console=serial` (только ВМ).
- **`ssh-port`** — на Ubuntu 24.04 через drop-in `ssh.socket` (`ListenStream`): `Port` в
  `sshd_config` там игнорируется.
- **`mpspace check`** — юниты `mproxy`, `nodejs-server`, `monit` и `auth.mp` (порт).
  **`auth`** — записать `auth.mp`.
- **`doctor`** — проверки хоста или сервера со счётчиком проблем.

## 7. Общие правила команд и `--json`

- У всех команд всех частей есть `--json`. Ответ — **конверт**:

  ```json
  {"ok": true,  "data": …}
  {"ok": false, "error": "текст для человека"}
  ```

  Код возврата 0 или 1, Ctrl-C — 130. Панель и хаб читают только `--json`.
- Без `--json` — текст для человека. Ошибка — `✗ …` в stderr.
- Деструктивное в скриптах — с `--yes`. В меню и панели — подтверждение номером сервера.
- Одна правка за раз — блокировка `/run/<часть>/lock`. Вторая команда ждёт или пишет «занято».
- **Секреты — через stdin:**
  - пароль modlink — `--password -`;
  - таблица proxyveth — `table put`;
  - пароль root и ключ — `pcs-node passwd`/`key` со stdin.

### 7.1 Долгие команды и обрыв связи (с 11.10.2026)

Раньше долгое (обновление, установка hivelink, перенос modlink, sync) жило, пока живо
SSH-соединение или HTTP-запрос панели: обрыв — процесс убит посреди работы, итога не видно.
В панели это давало «ответ панели не JSON (HTTP 200)» — ответ обрывался на середине.
Теперь долгое **идёт фоном юнитом systemd** на машине, а терминал и панель только смотрят:

| откуда | что уходит в фон | как |
|---|---|---|
| `pcs` в терминале хоста | `update`, `host-setup` (и `install.sh`), `server create`, `mpspace install` | задание хаба (`pcs-job-ID`, `/var/lib/pcs/jobs`) — после всех вопросов |
| части в терминале (хост или сервер) | `modlink setup`, `migrate` (не `--dry-run`), `uninstall --yes`; `hivelink install`, `uninstall`; `proxyveth setup`, `mode`, `sync`, `up/down/restart all` | `pcs/core/bg.py`: команда перезапускает себя юнитом `pcs-bg-ID`, журнал — `/var/lib/pcs/bg`; подтверждения спрашиваются ДО ухода в фон |
| панель | те же команды частей через `/api/run`, `ml`-кнопки (перенос) | задание хаба вида `part`; браузер опрашивает `/api/jobs/ID`, при обрыве связи ждёт и спрашивает снова |

- В терминале сначала строка `▸ задание … / ▸ в фоне …` и подсказка. Дальше идёт журнал.
  Связь оборвалась или нажат Ctrl+C — работа продолжается.
- Посмотреть снова:
  - `pcs job` — список (задания хаба и фоновые запуски хоста, новые сверху);
  - `pcs job ID` — журнал; если задание ещё идёт, журнал показывается до конца;
  - `pcs job --server N [ID]` — то же на сервере (там это `pcs-node bg`). Подсказку с номером сервера печатает сама часть на сервере.
- В фон уходит только человек в терминале (stdin и stdout — TTY, root, есть systemd).
  Хаб, панель, таймеры, `--json` и всё внутри задания (`PCS_BG=1`) работают как раньше.
- Подтверждения, данные в терминале, доходят до фоновой копии через `PCS_BG_CONFIRMED=1`.
  Блокировку берёт уже фоновая копия, иначе передний процесс и фон ждали бы друг друга.
- Панель:
  - на странице хоста раздел «Фоновые задания», у каждого «Журнал»;
  - GET при сбое связи повторяется до 4 раз;
  - если POST оборвался на ответе, панель честно пишет «действие могло выполниться — Обновить».
- **«Повторить»** (с 23.10.2026): упавшее или оборвавшееся задание хаба (`pcs job ID --retry`, в
  панели — кнопка под журналом) запускается ещё раз с теми же параметрами. Параметры лежат в
  `ID.params` (600), пока задание идёт; упало или процесс исчез (перезагрузка хоста) — переезжают в
  `ID.retry`, повтор их забирает (второй раз — уже у нового задания). **Создание ВМ при повторе
  продолжает ту же ВМ**: номер ВМ пишется в параметры сразу после выбора; ВМ с этим номером и
  сниппетом `pcs-<id>.yaml` есть — не создаётся заново, а запускается (если выключена), дальше
  шаги с первой загрузки: адрес, cloud-init (сделанный — пропускается), ядро, код, proxyveth,
  modlink, mp.space — все повторяемы.
- Скачивания (3proxy, sing-box, yaspeed) при сбое сети или DNS повторяются сами через 5, 15 и
  30 с (`util.download`): на новой ВМ DNS моргает, пока перезапускается resolved.
- Проверено на стенде (23.10): создание тестовой ВМ оборвал (`systemctl stop pcs-job-…`) сразу
  после доставки кода — «Повторить» продолжил ту же ВМ, сделанное пропустил, за минуту дошёл до
  «Готово»; пароль root — из первого запуска.
- **Проверено на стенде.** Обрывал SSH через 4–5 с после запуска:
  - `pcs host-setup` (hivelink + modlink) доработал — `pcs job` показал «готово» и весь журнал;
  - `pcs proxyveth sync --server 2000` доработал на сервере — `pcs job --server 2000`.

## 8. proxyveth — из прокси сетевой интерфейс

### 8.1 Режимы

| | `usb` (бывший vmodem) | `gw` (бывший proxyveth-virt) |
|---|---|---|
| что видит сервер | USB-устройство 12d1:14dc «HUAWEI_MOBILE», драйвер `cdc_ether`, интерфейс `ethN` | veth-интерфейс `pvN` |
| адрес у сервера | DHCP от «модема»: 192.168.N.100, шлюз и DNS — 192.168.N.1, аренда сутки | 192.168.N.100/24 сразу на `pvN` |
| предел | ~40–55 модемов: у каждого своя USB-шина, а шин в ядре не больше 63 | 1–254 модема, около 47 МБ ОЗУ на один |
| USB reset, перезагрузка модема | как у настоящего: USB пропадает и возвращается | нет USB |
| mp.space | ставит свою сторону сам (udev → udhcpc → свои таблицы) | видит интерфейс с адресом; маршрутизацию по источнику делает proxyveth |
| N и N+200 | нельзя вместе: делят таблицу маршрутов mp.space; 153–155 заняты | можно |

На сервере всегда один режим. Сменить — `proxyveth mode gw|usb --yes`: всё своё снимается
и поднимается в новом режиме.

### 8.2 Таблица модемов

Колонки:
- `n` — номер модема для сервера;
- `real` — `81`, `192.168.81.1` или `192.168.81.100`; пусто — real = n;
- `proxy` — `host:port:login:pass` (в пароле может быть `:`) или вместо неё четыре колонки
  `host`/`port`/`login`/`password` (есть синонимы);
- `enabled` — по желанию: `0`, `нет`, `выкл`, `-` выключают строку.

Проверки (`pcs.core.table.lint`). Брак называется поимённо, хорошие строки работают:
- n вне 1–254;
- n совпадает с сетью самой машины;
- n дважды — не берётся ни одна из строк;
- в режиме usb: N и N+200 вместе, 153–155;
- кривая прокси, пробел в логине или пароле;
- ⚠ два модема на одной прокси — смена IP у одного меняет у всех.

**Источник:**
- `proxyveth source <ссылка>` — ссылка на Google-таблицу прямо из адресной строки (сама
  станет CSV; таблица должна открываться по ссылке) или путь к файлу.
- После каждого удачного чтения кладётся локальная копия `/etc/proxyveth/table.csv`.
- Google недоступен — берётся копия, с предупреждением.
- В таблице ни одной годной строки — она считается сломанной, копия остаётся прошлой.
- `proxyveth source local` — главной становится локальная копия. Её правят:
  - `proxyveth table edit` — в `$EDITOR`;
  - `proxyveth table put` — CSV со stdin, так сохраняет панель;
  - вернуть Google — `source <ссылка>`; `table pull` — перечитать Google в копию.
- **Защита:** если таблица требует снести больше половины модемов, без `--force` ничего
  не сносится.

### 8.3 Команды

```
proxyveth on | off [--yes]            включить / выключить целиком (ниже)
proxyveth mode [usb|gw] [--yes]       режим; смена — снять всё своё и поднять в новом
proxyveth source [URL|local]          источник таблицы
proxyveth table [show|pull|edit|put]  показать / из Google / копия в $EDITOR / копия со stdin
proxyveth lint                        проверить таблицу, ничего не трогая
proxyveth sync [--force]              привести модемы к таблице (таймер — сам, раз в ~2 мин)
proxyveth up|down|restart N|all       поднять / остановить / пересоздать; down и restart всех — с --yes
proxyveth status [--wan]              быстрый тест; --wan — долгий: внешний IP через каждый модем
proxyveth problems                    только проблемные
proxyveth diag N                      прокси → логин → модем → SIM → интернет
proxyveth rotate N | reboot N         смена IP / перезагрузка настоящего модема (в меню и панели их нет)
proxyveth doctor                      окружение
proxyveth setup                       подготовить сервер (зовёт хаб); без режима — подсказка
proxyveth version
```

**Выключатель (`on|off`, в панели — переключатель над виртуальными модемами; с 23.10.2026).**
Как у modlink. Выключен (`"on": false` в `config.json`) — модемы и всё своё сняты (как при смене
режима: `teardown`), таймер sync выключен, при загрузке ОС ничего не поднимается: модули
`dummy_hcd` и гаджетов не грузятся, шин USB под модемы нет — сервер стартует быстрее (на
ВМ 2000 с 10 модемами: 19,3 с → 13,9 с; там, где загрузка подвисала на эмуляции USB, — заметно
больше). Таблица, режим, настройки и собранный `dummy_hcd` остаются. Пока выключен: `sync`
таймера пропускается молча, ручные `sync`/`up`/`down` — отказ с подсказкой, `status` — пусто,
`setup` (`pcs update`) не поднимает, `mode` только запоминает режим. `on` — подготовить режим,
таймер, модемы по таблице (на ВМ 2000 — 10 модемов за 82 с). Флага нет — включён, как всегда.

### 8.4 Строка состояния (`Row`) — одинакова в обоих режимах

```json
{"n": 201, "real": 81, "proxy": "188.134.88.13:16021", "state": "ok",
 "problems": [], "iface": "eth1", "ext_ip": "94.25.229.40", "since": 1760000000}
```

| `state` | значение |
|---|---|
| `ok` | работает |
| `warn` | наша сторона цела, но модем не работает: сломан апстрим (прокси, логин, SIM, нет связи, портал оператора, нет интернета) или сервер ещё не взял модем (`side`) |
| `broken` | сломана наша сторона: юнит, маршрут, гаджет, адрес |
| `absent` | модема нет |
| `disabled` | выключен в таблице |
| `stopped` | остановлен вручную (`proxyveth down N`): sync его не поднимает, пока не `up` |
| `rebooting` | перезагружается (как настоящий: USB вынут) |

У `warn` есть поле `side` (режим usb, с 12.10.2026):
- `upstream` — беда за прокси; панель пишет «апстрим»;
- `server` — своя сторона сервера: сервер (mp.space) не видит USB-устройство, у `ethN` нет
  `192.168.N.100`, пропало правило маршрутизации. Так бывает минуту-две после загрузки сервера
  или перезагрузки модема. Панель пишет «сервер», в сводке — «ждут сервер».

**Классы диагностики апстрима:**

| класс | что |
|---|---|
| `proxy-down` | прокси не отвечает |
| `proxy-error` | рвёт соединение — лимит? |
| `proxy-auth` | логин или пароль, в том числе код 2 на соединении |
| `modem-blocked` | прокси не пускает в сеть модема — не ген1 |
| `modem-unreachable` | 192.168.real.1 недоступен |
| `sim` | проблема с SIM |
| `no-data` | у модема нет связи |
| `captive` | SIM не оплачена: портал оператора |
| `no-internet` | нет интернета через модем |

- Интернет проверяется двумя целями с повтором; поломкой считается, только если две
  проверки подряд неудачны.
- Сломанная прокси или SIM **не мешает созданию модема**: модем создаётся и ждёт, а
  `status` говорит, что не так. Так попросил пользователь.

**Выдержка апстрима (`up_grace`, режим usb, с 12.10.2026).**
- Что считается: беда за прокси, которая бывает, пока настоящий модем переподключается (смена IP,
  перезагрузка) — прокси молчит или рвёт, модем недоступен, нет связи, SIM, нет интернета.
- Как показывается: «апстрим» — только если такая беда держится дольше `up_grace` секунд
  (по умолчанию 1800 = 30 мин, это 6 проверок по 5 мин). До этого модем «работает», а в Row есть
  `note` — серым: «… — 3 мин; апстримом станет через 27 мин (при смене IP это норма)».
- Оповещения тоже ждут этот срок.
- Сразу, без выдержки — неверный логин/пароль прокси, блокировка, неоплаченная SIM: от ожидания
  они не пройдут.
- Настройка: `"up_grace": N` в `/etc/proxyveth/config.json`, 0 — как раньше, сразу.
- В панели у каждого модема — «диагн.» (долгий тест одного модема), **«остановить» / «поднять»**
  и **«пересоздать»** (`proxyveth restart N`: интерфейс снимается и поднимается заново). Над таблицей —
  «Быстрый тест» (`status`, своя сторона, секунды), «Долгий тест (внешний IP)» (`status --wan`) и
  «все модемы: поднять / остановить / пересоздать».

**Остановлен вручную (с 13.10.2026, как в proxyveth-virt 3.4).** `proxyveth down N` (или `all`) —
модем снимается и помечается в `/var/lib/proxyveth/stopped.json`; таймер sync его не поднимает
(раньше поднимал через 2 минуты). В `status` — `stopped`, в счёт «сломанных» не идёт.
`up N` / `up all` / `restart N` отметку снимают.

### 8.5 Режим usb — устройство

| что | где |
|---|---|
| модем N | netns `pvN`, гаджет configfs `/sys/kernel/config/usb_gadget/pvN` (ECM, 12d1:14dc, строки `HUAWEI_MOBILE`) на слоте `dummy_udc.K` |
| модуль ядра | `dummy_hcd` собирается dkms (пакет `proxyveth-dummy-hcd`), `MAX_NUM_UDC=64`; слотов по умолчанию 48. Исходник — по очереди, пока не соберётся: копия от прошлой сборки → копия в PCS (`pcs/proxyveth/files/dummy_hcd-6.8.c`, ядро v6.8, для Ubuntu 24.04 — без сети) → `linux-source` в системе → GitHub → git.kernel.org → пакет `linux-source-6.8.0` из зеркала Ubuntu. Не собрался ни один — ошибка со списком попыток |
| MAC | со стороны сервера `0c:5b:8f:27:9a:64` (как у всех E3372h), со стороны модема `00:1e:10:1f:00:00` |
| сеть | в netns: `usb0` 192.168.N.1/24 и tun `pvtun0` 172.20.0.1/30 |
| юниты | `proxyveth-dns@N` (dnsmasq, DHCP ровно .100, аренда 24 ч), `proxyveth-px@N.socket` + `.service` (ретранслятор), `proxyveth-sb@N` (sing-box), `proxyveth-web@N` (веб-морда), таймер `proxyveth-sync.timer` |
| настройки | `/etc/proxyveth/config.json`, `/etc/proxyveth/usb/<N>/{singbox.json,dnsmasq.conf,env,proxy.pass,spec.json}` |
| состояние, журнал | `/var/lib/proxyveth`, `/run/proxyveth/state.json`; `/var/log/proxyveth` |

**Как идёт трафик:**
1. Клиент сервера (mp.space) шлёт пакет на `ethN`.
2. Пакет приходит в netns в `usb0`; правило `from 192.168.N.0/24 lookup 100` ведёт его в
   `pvtun0`.
3. sing-box (стек **system**) держит соединение и открывает его через SOCKS5 на
   `127.0.0.1:1080` внутри netns.
4. Это сокет systemd `proxyveth-px@N.socket` (`NetworkNamespacePath`); его принимает
   `systemd-socket-proxyd` уже на самом сервере.
5. Тот соединяется с прокси ген1 по основному каналу.

Своей сети наружу у netns нет, veth и NAT на сервере тоже нет.

**DNS модема:**
- dnsmasq → `127.0.0.1#5353` (direct-inbound sing-box) → `hijack-dns`;
- DNS-сервер sing-box — `tcp://192.168.real.1` через прокси, потому что UDP через ген1
  не ходит;
- любой DNS клиента, в том числе прямо на 8.8.8.8, тоже уходит к DNS настоящего модема
  (правило `port 53 → hijack-dns`).

**Веб-морда** (`modem_web.py`, `proxyveth-web@N`):
- процесс работает на сервере, а слушающий сокет `192.168.N.1:80` — внутри netns (через `setns`);
- отдаёт HiLink настоящего модема (`192.168.real.1` через прокси) и переписывает в
  ответах адреса на виртуальные;
- опасные записи (подсеть DHCP, пароль, прошивка, сброс) не пропускаются; обходы
  фильтра (`http://…`, `//`, `%xx`, регистр) закрыты;
- SMS не закрыты: их закрывает mobilink на ген2;
- перезагрузка через веб-морду (`Control=1`): USB «вынимается» и возвращается, когда
  настоящий модем снова отвечает (≈26–31 с на стенде).

**Сторона сервера:**
- если стоит mp.space (`/usr/local/bin/modem-interface-setup.sh`), адрес и маршруты
  делает его udev и udhcpc;
- иначе (`hostside: auto|on`) — свой udev-хук и udhcpc с таблицей `100 + N % 200` и
  правилом `from 192.168.N.100`.

`/etc/systemd/network/10-proxyveth-cdc.link` с `NamePolicy=` оставляет ядерные имена
`ethN`: у всех модемов один MAC, имя `enx…` досталось бы только первому.

**Создание — стратегия `serial:3` (с 13.10.2026):** по одному — следующий модем, когда сервер
взял адрес прошлого, и ещё пауза 3 с. 40 модемов — минут 7, зато ровно: пачками (`window:5`,
5 «в пути») сервер с mp.space захлёбывался, а 12.10 рабочая ВМ при подъёме 40 модемов падала.
- В журнале sync — каждый модем: «✓ модем 205: сервер взял за 8 с (5/40)».
- `proxyveth-sync` идёт с `Nice=10` и низким приоритетом диска; после загрузки — через 40 с.
- Другая стратегия — `"strategy"` в `/etc/proxyveth/config.json`: `window:W`, `fixed:B:G:P`, `all`.
  При переезде с vmodem старая стратегия не переносится.

**Лестница починки (`sync` и таймер):**
1. перезапуск юнита systemd;
2. переподключение USB (unbind/bind со стороны сервера);
3. пересоздание модема;
4. другой слот UDC;
5. после 3 неудач подряд — пауза 10 минут.

**Пустые слоты.** У пустого слота `dummy_hcd` отвязан от драйвера: в `lsusb` нет десятков
пустых root hub, root hub есть только у воткнутых модемов. Перед подключением модема шина
его слота возвращается.

**Ещё в config.json (перешло из vmodem, в меню и панели нет):**
- `proxy` — прямые прокси на каждый модем, юнит `proxyveth-proxy`: SOCKS5+HTTP на
  `base_port + N`, выход с адреса модема;
- `notify` — Telegram или webhook.

### 8.6 Режим gw — устройство

| что | где |
|---|---|
| модем N | netns `pvN`; veth: на сервере `pvN` 192.168.N.100/24, в netns `eth0` 192.168.N.254/24 |
| туннель | sing-box tun `pvtun0` в netns (10.0.N.1/30) → SOCKS5 ген1 |
| маршрутизация | `ip rule from 192.168.N.100 lookup 1000+N priority 30000+N`; в таблице — default через .254 |
| выход sing-box к прокси | с адреса .254 через сервер: NAT `-s 192.168.N.254/32 -o <основной канал> MASQUERADE` с пометкой `pcs:proxyveth` |
| в netns | DNS в туннель разрешён, остальной UDP — DROP (ген1 его не возит, а клиенты mp.space заливают тысячами пакетов); MASQUERADE на tun; TCPMSS |
| real ≠ n | `192.168.N.1:80` — посредник `proxyveth-hostfix@N`: подменяет `Host`/`Location`, иначе прошивка отвечает 307; DNS к `192.168.N.1:53` — DNAT на `192.168.real.1:53`, в туннель |
| real = n | 192.168.N.1 маршрутизируется в tun прямо к настоящему модему |
| юниты | `proxyveth-gw@N` (sing-box), `proxyveth-hostfix@N` (посредник), общий `proxyveth-sync.timer` |
| починка | `apply()` чинит лёгкое без пересоздания (юнит, tun, маршрут, правило, таблица, NAT); тяжёлое — пересоздание с нарастающей паузой 0 → 2 → 5 → 10 → 20 → 30 мин. В старом watchdog модем после 3 неудач бросался навсегда |
| основной канал | `pcs.core.net.uplink_route()` — явно, а не «первый default из main» |

### 8.7 Переезды

- **С vmodem 4.x** (`proxyveth setup` сам):
  - переносит источник таблицы и настройки из `/etc/vmodem/config.json`, ставит режим `usb`;
  - снимает старые модемы (`vmN`) и юниты `vmodem-*`;
  - поднимает модемы по-новому;
  - удаляет `/etc/vmodem`, `/usr/local/sbin/vmodem*`, `/usr/local/lib/vmodem`, старые udev,
    `.link`, networkd- и sysctl-файлы;
  - переименовывает пакет dkms.
- **С proxyveth-virt 3.4:** при наличии `/etc/proxyveth/env` режим определяется как `gw`.
  - Источник берётся из `API_URL`/`SHEET_CSV_URL`/`SHEET_ID`.
  - Снимается **только узнаваемо своё**: `ns_N`, `mdmN`, правила по его `config.json`,
    `/etc/netns/ns_N`, его юниты и `/usr/local/bin/proxyveth.py`.
  - Чужое (mp.space, modlink и его sing-box) не трогается.
  - **На рабочей ВМ 200 (90 модемов) не запускался** — только по команде.

## 9. modlink — из интерфейса прокси

Работает поверх **любых** интерфейсов — настоящих модемов или proxyveth.
**С 13.10.2026 — на 3proxy** (раньше sing-box) и по образцу modlink для Windows (ветка `app-v2`
репозитория Tovarish666/modlink): режимы портов, ссылки ребута и реконнекта, «Копировать» на
4 варианта, TCP и UDP, проверки внешнего IP. Почему 3proxy: сервис `auto` — HTTP и SOCKS5 (с UDP)
на одном порту, процесс ~7 МБ на 20 прокси против ~55 МБ у sing-box (замер на стенде).

**Выключатель (с 15.10.2026).** modlink по умолчанию **выключен**: `modlink-3proxy` и демон
`modlink` остановлены и выключены, своих портов в `ss -tulpn` нет, резерв портов снят. Ставится
(`modlink setup`, `pcs update`) — но не запускается. Запуск — только по явному распоряжению:
`modlink on` или флажок «modlink» сверху вкладки modlink в панели; `modlink off` — всё
остановить (таблица и настройки остаются). Флаг — `"on"` в `/etc/modlink/config.json`.
Перенос из modlink-linux (`migrate`) — тоже явное распоряжение: включает. У выключенного
таблицу можно править и применять (`apply` пишет конфиг и `applied.json`, но ничего не
запускает); включили — работает по применённой таблице.

### 9.1 Таблица — `/etc/modlink/proxies.json` (600)

| поле | что | куда уходит |
|---|---|---|
| `id` | постоянный номер строки: N для адреса 192.168.N.x, если свободен, иначе с 1001; удалённые номера не переиспользуются | в панели — «№» |
| `enabled` | строка активна | выключенные не попадают в конфиг |
| `name` | метка | интерфейс |
| `login`, `password` | доступ к прокси (печатный ASCII; в логине нельзя `:`). **Логины не повторяются**: у 3proxy один список пользователей | `users` 3proxy |
| `port` | порт прокси, **постоянный**; может быть общим у нескольких строк — модем выбирается по логину | `auto -pPORT` |
| `lan_ip` | адрес интерфейса на сервере | свой порт — `-e lan_ip`; общий — `parent 1000 extip lan_ip 0` у логина: именно это привязывает трафик к модему |
| `modem_ip` | веб-интерфейс Huawei | HiLink API: реконнект, ребут, проверка |
| `reboot_port` | порт ссылки ребута; 0 — нет | `GET http://<ip>:<порт>/reboot[/<пароль>]` |
| `reconnect_port` | порт ссылки реконнекта; 0 — нет; может совпадать с `reboot_port` (один слушатель, два пути) | `GET http://<ip>:<порт>/reconnect[/<пароль>]` |
| `interval_min` | автореконнект, минут (0 — выкл) | таймер в демоне |
| `protect` | защита строки (по умолчанию **выкл** с 24.10.2026), §9.5 | запреты 3proxy |

- **Режим портов** (§9.7, как в modlink для Windows) — только по явной команде, порты сами не съезжают:
  - `triples` — у строки свои три порта подряд: прокси P, ребут P+1, реконнект P+2;
  - `shared` — у всех один порт прокси (модем — по логину) и один порт управления; ссылки —
    `/reconnect/<пароль строки>` и `/reboot/<пароль строки>` (пароль в пути: браузер не считает
    это прокси-авторизацией, в отличие от `http://login:pass@`). Подходит и HTTP Basic.
  - Новая строка (`auto`) — свободная тройка от базового порта или общие порты.
- Порт прокси не бывает портом управления; на общем порту управления пароли строк разные.
- Правки вступают в силу **только после `modlink apply`**: демон берёт строки из
  `/var/lib/modlink/applied.json`. `list` и `status` показывают `pending`, если есть
  неприменённые правки.
- Перенос с прежнего modlink (sing-box) — сам, при обновлении: порты и пароли как были,
  реконнект на прежнем порту, ребута не было — `reboot_port = 0`.

### 9.2 Устройство

- **`modlink-3proxy.service`** — 3proxy 1.0.0 (`/usr/local/lib/pcs/3proxy`, из официального .deb,
  сверка SHA-256; бинарник 330 КБ, нужны libssl3, pcre2, zlib, zstd) с `/etc/modlink/3proxy.cfg`:
  - `auth strong`, `users` — только включённые строки; `maxconn 5000` (у 3proxy по умолчанию 100 на сервис);
  - на каждый порт прокси — `flush`, правила строк, `auto -pPORT` (HTTP CONNECT + SOCKS5 на одном порту);
  - правила строки по порядку (первое совпавшее решает): без защиты — `allow` своего `modem_ip`;
    `deny` частных сетей, 127/8, CGNAT, multicast (у всех); только TCP — `deny … UDPASSOC`;
    с защитой — `deny` сайтов операторов (по имени, только `CONNECT,HTTP,HTTPS`: на UDP 3proxy
    сверяет имя с IP и рубил весь UDP), своих сетей и опасных портов; `allow логин`
    (на общем порту — с `parent 1000 extip lan_ip 0`);
  - трафик TCP и UDP и задан WAN IP — `-Ni<WAN IP>`: его 3proxy сообщает клиенту для UDP ASSOCIATE;
  - журнал каждого соединения — только с `access_log` (`/var/log/modlink/3proxy.log`, 3 дня).
- **`modlink apply`**: конфиг → `systemctl reload` (SIGUSR1: 3proxy перечитывает, соединения не
  рвутся, PID тот же) → проверка, что все порты слушают; не вышло — перезапуск; порт так и не
  поднялся — прежний конфиг обратно и ошибка с журналом.
- **Свои порты — в `net.ipv4.ip_local_reserved_ports`** (`/etc/sysctl.d/91-modlink-ports.conf`):
  на ВМ с mp.space `ip_local_port_range = 1024–65535`, и исходящие соединения брали бы порты прокси
  и ссылок (на стенде так и было: «порт занят» на ровном месте). Чужие резервы не трогаются.
  Занятость порта проверяется по LISTEN (`/proc/net/tcp`), а не пробным bind.
- **`modlink.service`** (`modlink daemon`):
  - ссылки `GET /reconnect` и `GET /reboot` на портах управления. Строку выбирает: пароль или логин
    в пути → HTTP Basic → единственная строка порта. Браузеру — страница «было → стало» (старый IP
    зачёркнут, новый зелёным) или «перезагрузка отправлена»; скрипту (или `?json`) — `{ok, ip?}` /
    `{ok:false, error}`. Коды 200 / 401 (общий порт без пароля) / 403 (не тот пароль) / 404 / 405 /
    409 (уже идёт) / 502 (модем отказал);
  - автореконнект по `interval_min` (молчит, если порт реконнекта держит кто-то ещё — старая панель);
  - раз в час — внешний IP через каждый прокси (`wan_check`), раз в день в 12:00 — скорость
    (`speedtest`, по умолчанию выкл: трафик модема) → `/var/lib/modlink/checks.json`;
  - SIGHUP — перечитать; состояние — `/run/modlink/state.json`.
- **Реконнект через HiLink:** свежая пара SesTokInfo перед каждым POST → передача данных
  выкл → режим сети `02` и обратно к исходному → данные вкл (3 попытки) → ждём
  `ConnectionStatus 901`.
- Новый внешний IP узнаётся запросом с привязкой к `lan_ip`, то есть тем же путём, что идёт прокси.
- **Ребут** — `device/control Control=1`. **Скорость** — yaspeed 1.0.1 (`--source-ip lan_ip`),
  ставится по первому запросу в `/usr/local/lib/pcs/yaspeed`.
- Журнал строки — `/var/log/modlink/<id>.log` (реконнекты, ребуты, скорость), при 1 МБ — в `.1`.
- **Проверено на стенде (13.10.2026, ВМ 2000, 20 модемов):** каждый порт выходит через свой
  модем (HTTP и SOCKS5); общий порт — три логина, три разных IP; запреты (чужой 192.168.x, mts.ru по
  имени и через socks5h, порт 25, 127.0.0.1) — 403/отказ; UDP (DNS к 8.8.8.8 через SOCKS5 UDP) — есть,
  в частную сеть — нет; смена пароля и apply — reload, тот же PID; реконнект по ссылке — страница
  «188.162.65.134 → 94.25.228.98»; 3proxy на 20 прокси — 7 МБ.
- Ограничение: запрет по имени срабатывает, когда имя прислал клиент (HTTP, `socks5h`). Если клиент
  сам перевёл имя в IP (`socks5`), сайт оператора по имени не узнать (sing-box узнавал по SNI);
  частные сети и порты закрыты всегда.

**Конфиг по таблице (`import`, в панели — «Конфиг по таблице»; с 23.10.2026).** Обратное
«Копировать»: клиентам уже розданы строки `Ip:port:log:pass | ReBoot | ReConnect` (или без
ReBoot) — modlink подстраивается, чтобы каждая работала ровно так. Нужно при переезде с modlink
для Windows, когда старый конфиг не достать.
- Источник — вставка из таблицы (табуляция), CSV по ссылке на лист Google-таблицы (доступ по
  ссылке) или файл. Колонки и их порядок любые: берутся ячейки `ip:порт:логин:пароль` и ссылки
  `http://ip:порт/reboot|reconnect[/пароль]`; шапка, имена клиентов, пустые строки — мимо.
- Модем строки — по логину `modemN` (модем 192.168.N.1: так строки называет modlink и для
  Windows, и здесь; подсеть модема хранится в нём самом и переезжает вместе с ним). Логин не такой
  или `--map order` — свободные модемы машины по порядку (основной канал — не модем).
- Строка того же модема или логина правится (интервал, имя, защита — как были), новой — добавляется;
  строки не из таблицы остаются (`--replace` — убираются). Порты, логины, общий порт управления —
  проверки §9.1; не сходится с остальными строками — отказ с подсказкой `--replace`.
- Настройки: `wan_ip` — адрес из таблицы (в таблице один адрес — иначе отказ), `mode` (общий порт
  у всех — shared), `base_port` — первый порт таблицы. Только записываются: порты не пересчитываются.
- Порт таблицы слушает чужая программа — отказ до записи. Модема строки на машине нет — строка
  пишется (заработает, когда модем появится), в плане предупреждение.
- `--dry-run` (в панели — «Проверить») — только план: добавить / поправить (что именно) / как есть /
  убрать. Потом запись, `apply`, `--on` — и включить modlink.
- Проверено на стенде: ВМ 2000, три строки — `modlink export` после импорта совпал с таблицей
  символ в символ, прокси HTTP и SOCKS5 ходят в интернет через свои модемы, чужой пароль — 407.

**Перенос из modlink-linux (`migrate`):**
- строки с id N, логином `modemN`, портами прокси `base+2i` и реконнекта `base+2i+1` (как были),
  без ребута; пароли: из `modems.conf`, из `singbox.json` или тот sha256, что придумывал `modlink-server`;
- старый `modlink.service` (их sing-box, имя совпадает с нашим демоном) останавливается,
  копия — в `/etc/modlink/legacy/`;
- старая панель (порт 5000) без `--stop-panel` не останавливается;
- `/usr/local/bin/sing-box` не трогается.

### 9.5 Защита строки (`protect`)

Мобильная сеть узнаёт абонента по IP. Личный кабинет оператора, оплата с баланса,
подписки и веб модема (SMS, USSD через HiLink) открываются **без пароля**. Через прокси
всё это получил бы любой клиент. Поэтому у каждой строки есть галочка «защита»:
в панели — колонка «защита» (активна / не активна), в терминале — `modlink protect`.

| | защита **активна** | защита **не активна** (по умолчанию с 24.10.2026; ген1, для себя) |
|---|---|---|
| сайты и ЛК операторов: mts.ru, megafon.ru, beeline.ru, tele2.ru, t2.ru, yota.ru, sbermobile.ru, vtbmobile.ru, gpbmobile.ru, motivtelecom.ru, danycom.ru, letai.ru, volnamobile.ru, win-mobile.ru (с поддоменами) | закрыты по имени, которое прислал клиент (HTTP, `socks5h`); с 13.10.2026 голый IP не распознаётся (§9.2) | открыты |
| порты 23, 25, 135, 137–139, 445, 465, 587, 1900, 2525, 6881–6889 (telnet, почта, SMB, SSDP, торренты) | закрыты | открыты |
| веб своего модема (`modem_ip`) | закрыт | **открыт** — только `modem_ip/32` |
| остальные частные адреса, 127/8, CGNAT 100.64/10, IPv6 | закрыты | закрыты |

- **Свои дополнения** — `/etc/modlink/protect.json`:
  `{"domains": ["lk.example.ru"], "cidrs": ["10.200.0.0/16"], "ports": [8291]}`.
  Испорченный файл — `modlink apply` откажет с понятной ошибкой.
- Правки вступают в силу после `modlink apply`. После обновления кода конфиг сам
  пересобирается (`resync`): у строк защита — как была.
- **По умолчанию новые строки — без защиты** (с 24.10.2026, по просьбе владельца):
  `modlink add` без `--protect`, «+ Модем», «Из интерфейсов», «Конфиг по таблице».
  Включить — галочка «защита» в панели, `modlink add --protect` или
  `modlink protect ID|all on`.
- Задержки на первом пакете больше нет: у sing-box `sniff` ждал байты клиента до 0,3 с, 3proxy так не делает.
- **Проверено на стенде (10.10.2026, ещё на sing-box)**, трафик из ВМ 2000 через modlink хоста:
  с защитой — ЛК МТС/Мегафона закрыт по имени, по CONNECT и по голому IP, веб модема,
  соседние ВМ, сам хост и 127.0.0.1 закрыты; без защиты — ЛК и веб модема открыты,
  соседи, хост и 127.0.0.1 по-прежнему закрыты.

### 9.6 modlink на хосте и виртуальные модемы из настоящих

Настоящие модемы можно воткнуть прямо в хост Proxmox. Цепочка в пределах одного хоста:

```
модем USB ─ hivelink (хост) ─ 192.168.N.100 ─ modlink (хост, защита снята)
          ─ прокси 192.168.88.254:порт ─ proxyveth в ВМ этого хоста ─ виртуальный модем ─ mp.space
```

- modlink на хост ставят `install.sh` и `pcs update --host`. Управление:
  `pcs modlink … --host`, меню «Прокси — modlink» с выбранным хостом, в панели — строка
  «modlink» на странице хоста → «Открыть» (`#/host/modlink`, та же таблица, что у ВМ).
- **Строке-поставщику защита нужна снятой.** proxyveth ходит через прокси к
  `192.168.real.1`: туда идут DNS виртуального модема (`tcp`, detour proxy) и проверка
  HiLink. С защитой эти запросы получат `reject`, и модем будет с предупреждением.
  `modem_ip` должен быть ровно `192.168.N.1`.
- `modlink export --table` (в панели — кнопка «Для proxyveth») печатает готовые строки
  `n,real,proxy,enabled`. N = real = номер настоящего модема, IP — основной адрес хоста
  (тот, что видят ВМ на vmbr0); другой адрес — `--ip`. Про строки с включённой защитой и
  с неверным `modem_ip` выводятся предупреждения. Строки вставляются в таблицу proxyveth
  ВМ (вкладка proxyveth → таблица или `proxyveth table put`).
- Прокси хоста слушает `0.0.0.0` с логином и паролем. Порт открыт и наружу, если роутер
  пробрасывает его на хост.
- Строки переносятся вручную; кнопку «хост → таблица ВМ» пользователь решил не делать (11.10).
- `export --table` берёт адрес из настройки **LAN IP** (§9.7), а если она пуста — основной
  адрес хоста.

**Старый modlink-linux на хосте** (бывает на хостах, где он стоял до PCS; так было на
megavolgadata). Его `modlink.service` — это его sing-box: держит порты прокси, имя
совпадает с нашим демоном. Признаки: `modlink status` — «юнит от старого modlink-linux»,
в панели — красный баннер. PCS его не трогает, пока не попросят:
- `modlink apply` откажет сразу с подсказкой (а не «нет sing-box» или «порт занят»);
- перенос: `modlink migrate --dry-run` (что перенесётся), затем
  `modlink migrate --force --stop-panel`. Строки — из его `modems.conf`, порты и пароли как
  были (клиентам ничего менять не надо), базовый порт и внешний IP — в настройки (§9.7),
  его юнит — в `/etc/modlink/legacy/`, старая панель :5000 останавливается.
  `--force` — потому что заменяет таблицу, если в ней уже что-то есть;
- в панели то же самое — кнопка «Перенести из modlink-linux» в баннере (сначала покажет
  строки, потом спросит).
- Защита у перенесённых строк включена; снять — галочкой или `modlink protect all off`.

### 9.7 Общие настройки (`modlink settings`, сверху вкладки modlink)

Как в modlink для Windows — карточка «Основная сеть» над таблицей. Хранятся в
`/etc/modlink/config.json` (прежнее `ext_ip` читается как `wan_ip`).

| настройка | что делает |
|---|---|
| **IP этого хоста** (`lan_ip`, пусто — авто: основной адрес машины) | адрес в локальной сети: в строках «Для proxyveth» (`export --table`) — их берут ВМ этого хоста |
| **Внешний IP** (`wan_ip`, пусто — авто: узнаётся при копировании) | адрес для строк и ссылок клиентам; его же 3proxy сообщает для UDP (`-Ni`) |
| **Базовый порт** (`base_port`, по умолчанию 10000) | от него порты новых строк и смены режима. Смена — порты **всех** строк заново в текущем режиме |
| **Режим портов** (`mode`: `triples` / `shared`) | «Разные порты (тройки)» / «Один порт (по логину)» — порты **всех** строк заново, §9.1. Порт занят чужим — отказ, ничего не меняется |
| **Трафик** (`traffic`: `tcp+udp` / `tcp`) | «TCP и UDP» или «Только TCP» (UDP ASSOCIATE запрещён) |
| **Внешний IP раз в час** (`wan_check`, вкл) | демон проверяет выход каждого прокси; в панели — колонка «Внешний IP» |
| **Скорость в 12:00** (`speedtest`, выкл) | раз в день yaspeed по каждому модему — это трафик модема |
| **Журнал соединений** (`access_log`, выкл) | каждое соединение 3proxy — в файл (много места при большом трафике) |

- `modlink settings` без аргументов — показать (`--json`: все поля + `lan_ip_now`, `renumbered`).
- После `base_port`, `mode`, `traffic`, `wan_ip`, `access_log` — `modlink apply`.
- `export --save` сохраняет WAN IP; `migrate` переносит `base_port` и `ext_ip` старой панели.
- Меню «Прокси — modlink» → «Настройки»; панель — `POST /api/targets/{id|host}/modlink/settings`.

### 9.8 Вкладка modlink в панели (как в modlink для Windows)

- Сверху: выключатель «modlink» (вкл — 3proxy и демон работают; выкл — ничего не запущено,
  портов нет; выключение — с подтверждением), состояние 3proxy и демона, «Применить» (правки
  таблицы → apply; у выключенного — заработает после включения).
- «Основная сеть»: IP хоста, внешний IP, базовый порт; режим портов и трафик — переключатели;
  галочки проверок и журнала.
- «Модемы»: **№ · IP · Порт · Логин · Пароль · Внешний IP** и действия в строке: Test (внешний IP
  через прокси + HiLink), ⟳ реконнект, ⧉ копировать строку, ▾ ещё (имя, IP модема, порты ребута и
  реконнекта, автореконнект, вкл, защита; «Ребут модема», «Спидтест», «Журнал»), ✕ удалить.
- «Копировать ▾»: только прокси / только ссылки ребута / только ссылки реконнекта / прокси + ребут +
  реконнект — таблицей по колонкам, «Копировать для таблицы» кладёт через табуляцию (в Google-таблицу
  встаёт по ячейкам).
- «+ Модем», «Диапазон», «Из интерфейсов», «Конфиг по таблице» (§9.3), «Для proxyveth», «Логи ▾»
  (3proxy / демон).
- 🔗 в строке — веб модема (IP модема строки) в отдельном окне (§13.9).
- **Автозаполнение (как в Windows-версии):** «+ Модем» берёт следующий № (наибольший + 1, иначе
  первый свободный) и сам заполняет строку: IP `192.168.N.100`, IP модема `192.168.N.1`, логин
  `modemN`, имя `modem N`, пароль (12 знаков), порты — следующая тройка после наибольшего (в
  режиме «один порт» — общий порт и base+1). Сменили № в новой строке — пересчитываются те поля,
  которые не трогали руками; сменили IP — IP модема встаёт `.1` той же сети. «Диапазон» — сразу
  строки «с № по №», занятые номера пропускаются.

## 10. hivelink — драйвер настоящих модемов

Модели: Huawei E3372, E3131, E353, Vodafone K5150/K5160. Ставится на хост Proxmox
**автоматически** (`install.sh`), в ВМ — по запросу (`pcs hivelink install --server ID`).

**Проход** (`hivelink.timer` раз в 15 с плюс udev на каждое появление устройства):

| шаг | что делает |
|---|---|
| Zero-CD | `12d1:1f01…` — модем отдался как CD-ROM; usb_modeswitch со своим конфигом — в CD-интерфейс **текущей** конфигурации (`-i N`), по 8 модемов разом, повтор для модема не раньше 25 с, после 3 попыток — пере-enumerate (ниже) |
| USB-конфигурация | перебор `bConfigurationValue` до `rndis_host`/`cdc_ether`; удачная запоминается в `/var/lib/hivelink/confmap`; не годится ни одна — модем ждёт переподключения |
| сеть | DHCP через systemd-networkd (`25-hivelink.network`: `UseDNS=no`, `DNSDefaultRoute=no`, без шлюза); таблица `2000+N`, правило `from 192.168.N.100 priority 31000+N` |
| данные | сессия HiLink → `dataswitch=1`; без связи — лестница починки (ниже), одна попытка не чаще раза в 180 с |
| фикс приёма | DKMS-патч `rndis_host`: параметр `rx_urb_size_override` (16384) вместо зашитых 2048 — download ≈1,3 Мбит/с без него |

**Сорок модемов разом (SpbVL-1, 23.10.2026).** Два проброшенных USB 2.0-контроллера,
хабы, 40 E3372 (HiLink, 12d1:14db). Что ломалось и как теперь:
- **Zero-CD не переключался никогда.** Ядро само ставит модему в Zero-CD конфигурацию 2 (MBIM);
  hivelink ставил cfg 1 — модем на это переподключается, ядро снова ставит cfg 2, и так по
  кругу (а шина — в сбросах). CD-интерфейс есть и в cfg 2: команда идёт туда, конфигурацию
  не трогаем. На стенде: 35 модемов из Zero-CD в HiLink за ~1,5 мин.
- **MBIM не нужен:** `cdc_mbim` запрещён (`/etc/modprobe.d/hivelink-modems.conf`: `blacklist`
  и `install … /bin/true`), при установке выгружается. Без него нет сорока `wwanN`, за
  которыми шли ModemManager и скрипты mp.space.
- **CD и microSD модемов:** `usb-storage` не берёт модемы Huawei (`quirks=12d1:PID:i` — Zero-CD
  и рабочие PID, чужие quirks целы; параметр — не длиннее 127 символов) — не бывает десятков
  `srN` с «critical medium error» и сбросами, от которых ВМ «сходила с ума». Модуль грузится из
  initramfs — тот пересобирается; сразу — отвязка от модемов и параметр в `/sys/module`.
  usb_modeswitch CD не нужен: он говорит с модемом через usbfs.
- **ModemManager** выключается при установке (флаг — снятие hivelink включит обратно), а
  модемам ставится его штатная метка `ID_MM_DEVICE_IGNORE` — даже включённый их не тронет.
- **eth0 — основной сетевой карте.** Как его терял: в initramfs нет `.link` netplan (он в `/run`),
  карту там называют `enp6s18`, eth0 освобождается — его берёт модем, и вернуть имя карте уже
  нельзя («File exists»), ВМ без сети. Теперь три ступени:
  - `/etc/systemd/network/10-hivelink-eth0.link` (MAC основной карты → `eth0`, MAC — из `.link`
    netplan с `Name=eth0`) — initramfs-tools кладёт его в образ, карта — eth0 с первой секунды;
  - модем, всё же получивший `eth0`, сразу уходит на свободное `ethN` от 64 (правило udev;
    модемам `ethN` оставлены — их ждёт mp.space);
  - `hivelink-eth0.service` до запуска сети: карта не eth0 — вернуть (модем с eth0 — в сторону).
  Нет правила netplan с `Name=eth0` (хост Proxmox) — ничего этого не делается.
- **initramfs** пересобирается, когда меняются `modprobe.d`, `.link` или правила udev hivelink —
  все они попадают в образ.
- Проверено на SpbVL-1 (23.10): перезагрузка с 40 модемами — eth0 у основной карты с самого
  начала, ни одного переименования из eth0; через минуту 40 модемов в HiLink, у всех адрес,
  `wwan` и ошибок CD нет; ещё через пару минут все «онлайн, LTE». Загрузку теперь держат службы
  mp.space `modem-hotplug@ethN` (~44 с), не hivelink.
- `hivelink doctor` проверяет всё это: cdc_mbim, CD/SD модемов, ModemManager, eth0.

**Лестница починки (с 17.10.2026): модем без связи не ждёт команды человека.** Чем дольше нет
связи, тем сильнее средство:

| ступень | что | когда |
|---|---|---|
| 0. дозвон | `dial Action=1` | «отключён», «сбой» (902, 904–906) |
| 1. откл → вкл | `Action=0`, 3 с, `Action=1` — то же, что `hivelink reconnect` | дозвон не помог; сразу — для зависших в 900/903 дольше `stuck_grace` (180 с) и для «онлайн без трафика» |
| 2. перерегистрация | данные выкл → режим сети `02` и обратно → данные вкл; режим и диапазоны возвращаются как были | откл → вкл не помог; сразу — для «нет регистрации» при SIM на месте (после 3 мин поиска сети самим модемом) |
| 3. перезагрузка модема | `device/control Control=1` | без связи дольше `heal_reboot_after` (600 с), не чаще `heal_reboot_every` (1800 с) на модем |

- «Онлайн без трафика»: раз в `netcheck_every` (300 с) TCP-соединение с адреса модема к
  `netcheck_host` (1.1.1.1:80, без полезной нагрузки); `netcheck_fails` (3) неудач подряд —
  ступень 1. Только если у адреса свой выход (правило `from 192.168.N.100` и маршрут по
  умолчанию в его таблице — наш или mp.space), иначе проверка врала бы.
- SIM не видна (`SimStatus` ≠ 1) — только в журнал: перезагрузкой SIM не вставить.
- Web-API молчит дольше `api_dead_after` (600 с), а адрес есть — пере-enumerate USB
  (`authorized` 0→1), не чаще `api_reenum_every` (1800 с).
- DHCP: `dhcp_max_tries` подряд, дальше раз в `dhcp_retry_every` (300 с) — не бросается
  навсегда; счётчик на интерфейс с его ifindex (модем вернулся под тем же именем — заново).
- Связь вернулась — лестница сначала. `auto_heal: false` — только дозвон, как раньше.
  Состояние — `/run/hivelink/state.json` (`heal`), журнал — `journalctl -t hivelink`.
- То же — в отдельном [hivelink](https://github.com/Tovarish666/hivelink) 2.1.0 (bash).

**Чужого не трогает:**
- **виртуальные модемы** (шина `dummy_hcd`/`vhci_hcd`) пропускаются везде: в выборке, в
  udev (`GOTO` до любого действия), в `.network` (`Path=!…`), при перезагрузке модуля;
- адрес `.100` на сетевухе хоста — не модем;
- уборка — только своих приоритетов 31001–31254 и таблиц 2001–2254;
- глобальные `rp_filter` и `gc_thresh` не меняет; `rp_filter=2`, `arp_*` — только на
  интерфейсах модемов.

**Сеть модемов:** `config.json: "net": "auto|on|off"`. При `auto` и стоящем mp.space адрес
и маршруты делает его udhcpc, а hivelink — только USB и HiLink: иначе два DHCP-клиента
дрались бы за интерфейс.
- **Модем без адреса при mp.space (с 24.10.2026).** mp.space настраивает модем
  (`modem-hotplug@ethN` → `modem-interface-setup.sh`) один раз на событие udev. При массовом
  включении часть запусков кончается «no valid IP obtained» (SpbVL-1, 23.10: 18 из 40), и модем
  оставался без адреса до следующего события. Теперь: нет IPv4 дольше `mp_grace` (45 с) —
  hivelink запускает ту же штатную настройку mp.space заново
  (`systemctl start --no-block modem-hotplug@ethN`), не чаще `mp_retry_gap` (60 с), после
  `dhcp_max_tries` — раз в `dhcp_retry_every`.

**Выключить модем (`hivelink off`, с 24.10.2026).** Два модема с одним N (два «62-х») мешают
друг другу: подсеть одна, работает в лучшем случае один. `hivelink off ПОРТ|ethN` отцепляет
модем от USB (`authorized=0`) и запоминает порт в `/etc/hivelink/off.json` — после
перезагрузки или переподключения проход снова его отцепит. По номеру N, если модемов с ним
два, — только с указанием порта (ошибка их назовёт). `hivelink on ПОРТ` — вернуть.
`hivelink off` без аргумента — список. В панели — кнопка в строке модема
(«Сетевые интерфейсы» → физические модемы), выключенный показан «выключен» с кнопкой включить.

**networkd:**
- установщик его не перезапускает: на Ubuntu — `networkctl reload` и reconfigure только модемов;
- на Proxmox — запускает, если не работал, и выключает `wait-online`, если тот не был
  включён (иначе загрузка ждала бы 2 мин). Перед этим — `ensure_base()` (§11.2), чтобы
  networkd не снёс маршруты хоста;
- `uninstall` гасит networkd, только если его запускал hivelink и других `.network` нет.

**DKMS-фикс:**
- версия ядра — из `/proc/version_signature` (Ubuntu) или последнего вхождения в
  `/proc/version` (Debian/Proxmox; в начале строки стоит `gcc …`);
- исходник `rndis_host.c` с git.kernel.org или зеркала; запасной путь — архив ядра.
  Для x.y.0 файл называется `linux-6.8.tar.xz`;
- повторный `install` ничего не пересобирает; initramfs пересобирается, только если в нём
  штатный `rndis_host`;
- `HIVELINK_SKIP_RNDIS_FIX=1` — без фикса;
- при Secure Boot — подсказка про регистрацию ключа MOK.

**Файлы:**
- `/etc/hivelink/config.json` (700);
- `/var/lib/hivelink`, `/run/hivelink`, `/var/log/hivelink` + journald (`-t hivelink`);
- udev `70-hivelink.rules`, `71-hivelink-ports.rules` (ссылки AT-портов `/dev/hivelink/…`),
  `41-hivelink-modeswitch.rules`.

**Команды:**

```
hivelink install | uninstall | status [--fast] [--json] | doctor [--json]   (--fast — без внешнего IP)
hivelink reconnect N | reset N|USB-порт | recfg N|USB-порт | dataon N|--all
```

**`status --json`:**

```
{version, installed, net, virtual,
 usb: {total, hilink, zerocd, stick, other, with_addr, ok},
 fix: {active, size, file, dkms, needed},
 modems: [{n, iface, driver, usb_port, usb_id, mode, cfg, addr, conn, conn_text,
           dataswitch, net, signal, ext_ip, errors}]}
```

**На стенде проверено:** на хосте ставится и собирает фикс; на ВМ с виртуальными модемами
видит 0 настоящих и 3 виртуальных и не меняет ни одного правила и маршрута. На настоящих
модемах ещё не запускался: Zero-CD, перебор конфигураций и HiLink перенесены из
e3372-driver один в один.

## 11. Сеть, DNS, sing-box — сквозные правила

### 11.1 Таблицы, приоритеты, пометки

| часть | таблицы | приоритет ip rule | пометка iptables |
|---|---|---|---|
| proxyveth usb, своя сторона сервера | `100 + N % 200` | авто (как mp.space) | — |
| proxyveth gw | `1000 + N` | `30000 + N` | `pcs:proxyveth` |
| hivelink | `2000 + N` | `31000 + N` | `pcs:hivelink` |
| ядро: адреса прокси → основной канал | `90` | `32765` | — |

- mp.space нумерует свои таблицы так же, как proxyveth usb (имена `modemK`, где K = 1 +
  октет % 200), а 253–255 у него — системные.
- iptables — только с `-m comment --comment pcs:<часть>`; уборка снимает только своё.

### 11.2 База машины — `pcs.core.net.ensure_base()`

- `/etc/sysctl.d/90-pcs.conf`: `kernel.panic=10`, `kernel.panic_on_oops=1`, `ip_forward=1`.
  Если ядро упадёт, сервер перезагрузится сам, а модемы поднимет таймер.
- **На хосте Proxmox** (есть `/etc/pve`) — `kernel.panic_on_oops=0`, явно: oops драйвера
  (модемы, dkms) не должен перезагружать хост со всеми ВМ. Прежние версии писали туда 1 —
  `pcs update --host` перепишет файл и снимет значение сразу (`sysctl -p`).
- `/etc/systemd/networkd.conf.d/10-pcs.conf`: `ManageForeignRoutingPolicyRules=no`,
  `ManageForeignRoutes=no`. Иначе любой `netplan apply` стирает маршрутизацию модемов и mp.space.

### 11.3 Адреса прокси — только через основной канал

`pcs.core.net.pin_proxies` при каждом sync ставит правило `ip rule priority 32765 to <IP
прокси> lookup 90`; в таблице 90 — маршрут по умолчанию основного канала.

**Зачем.** Скрипт mp.space на каждый воткнутый модем запускает `udhcpc`. Стандартный
скрипт udhcpc ставит маршрут по умолчанию через модем **без метрики**, то есть с метрикой
0, — лучше основного. mp.space удаляет его только через пару секунд. Соединение к прокси,
открытое в это окно, уходило в свой же туннель и размножалось петлёй: до 11 000
соединений, после чего прокси начинала отказывать.

### 11.4 DNS-фикс (`pcs dns`, `pcs-node dns-fix`, `pcs/core/dns.py`)

Механизм взят из исходного ProxyControlService и доработан:
0. Снять `chattr -i` с `/etc/resolv.conf`.
1. `/etc/systemd/resolved.conf.d/99-pcs.conf`: `DNS=…` (по умолчанию 1.1.1.1 8.8.8.8),
   `FallbackDNS=9.9.9.9 1.0.0.1`, `Domains=~.`, `DNSStubListener=yes`, `DNSSEC=no`,
   `DNSOverTLS=no`, `Cache=yes`.
2. Отдельный `/etc/netplan/99-pcs-dns.yaml` (600) только для интерфейсов с DHCP:
   `dhcp4/6-overrides: {use-dns: false, use-domains: false}`. `50-cloud-init.yaml` не трогается.
3. `netplan generate` — при ошибке drop-in откатывается. `netplan apply` — только если
   файл изменился и только после `ensure_base()`.
4. `/etc/resolv.conf` → симлинк на `stub-resolv.conf`, перезапуск resolved, `flush-caches`.
5. Проверка: `getent ahostsv4` для github.com, docs.google.com, mobileproxy.space и что на
   интерфейсах нет чужого DNS.

Сверх старого:
- oneshot `pcs-dns.service` при загрузке;
- снятие чужого `172.20.0.2`;
- повтор после установки mp.space;
- **проверка серверов** (с 24.10.2026, §17 п. 20). Перед записью каждому заданному серверу
  уходит 10 запросов по UDP. Ответил меньше чем на 9 — сервер «теряет», вместо него
  ставится рабочий из запаса: 9.9.9.9, 77.88.8.8, 1.0.0.1, 8.8.4.4, 149.112.112.112,
  77.88.8.1, последним — шлюз (роутер).
  - Заданные серверы запоминаются строкой `# PCS-WANT:` в том же файле (`pcs dns` без
    `--dns` и панель берут их, а не запасные).
  - Таймер `pcs-dns-check.timer` раз в 10 минут (`pcs-node dns-fix --watch`) проверяет
    снова. Заданный вернётся на место, только если ответил на все 10; стоящий сейчас
    держится при 9 из 10, чтобы не было дребезга. Не поменялось ничего — resolved не
    трогается.
  - Не ответил никто (сети нет, ранняя загрузка) — остаются заданные: хуже не делать.

На хосте без netplan (Proxmox) — только resolved/resolv.conf; проверка серверов та же.

### 11.5 sing-box

- Версия **1.14.2**, `/usr/local/lib/pcs/sing-box`, сумма сверяется (`pcs.core.singbox`).
  Один бинарник на proxyveth и modlink.
- **`/usr/local/bin/sing-box` чужой** — не читаем, не ставим, не удаляем. Там его держат
  modlink-linux (1.13.14) и proxyveth-virt (1.10.0): кто поставил последним, тот и прав.
  На ВМ 200 это ломало proxyveth-virt; починено там отдельным путём через `SINGBOX_BIN`.
- **Конфиги — только в формате 1.12+** (1.14 старый не принимает вовсе):
  - DNS-серверы `{"type": "tcp", "server": …, "detour": …}`, а не `"address": "tcp://…"`;
  - никаких служебных outbound `dns`/`block`: вместо них `{"action": "hijack-dns"}`,
    `{"action": "reject"}`;
  - никаких `sniff*` на inbound (`{"action": "sniff"}` в route);
  - никакого `domain_strategy` в dial-полях.

  Переменная `ENABLE_DEPRECATED_LEGACY_DNS_SERVERS=true` не спасает: следом падает
  outbound `dns`, удалённый в 1.13.
- sing-box и всё долгоживущее — **своими юнитами** (`…@N`), а не дочерними процессами
  oneshot-юнитов: иначе systemd убьёт их вместе с родителем.
- sing-box в netns — **без доступа к D-Bus** (`InaccessiblePaths=-/run/dbus/system_bus_socket`).
  Иначе он прописывает DNS своего tun (172.20.0.2, `~.`) в systemd-resolved по номеру
  интерфейса из netns. D-Bus общий, и на сервере под тем же номером оказывается `eth0`
  или сетевуха модема — весь DNS сервера уходил в никуда.

## 13. Веб-панель — HTTP API

### 13.1 Доступ

- `pcs-web.service`: `pcs web serve` → `pcs.web.server.main`. Порт **666**, слушает 0.0.0.0.
- Порт открывает и закрывает **сам пользователь**: пробрасывает на время работы.
- `pcs web on|off|status|passwd`. Порт 5000 на ВМ (старый modlink) не наш — не трогаем.
- Для разработки — фейковые данные:

  ```bash
  PCS_WEB_FAKE=1 python3 -c 'from pcs.web.server import main; main(["--port","6660"])'
  ```

- **`/etc/pcs/web.json` (600)** — формат пишет и читает `pcs.web.auth`, хаб пользуется им же:

  ```json
  {"user": "admin",
   "password": {"algo": "pbkdf2-sha256", "iterations": 600000, "salt": "<hex>", "hash": "<hex>"},
   "changed": 1760000000}
  ```

### 13.2 Вход и защита

| что | как |
|---|---|
| вход | `POST /api/login` с телом `{"user", "password"}`. Нужны заголовок `X-CSRF` (любое значение — чужая страница не пошлёт его без preflight) и свой `Origin`, если он есть |
| ответы входа | 200 + cookie `pcs_sid_666`; 401 — неверно; 403 — нет `X-CSRF` или чужой Origin; 429 — пауза; 503 — вход не задан |
| пауза после неудач | первые 5 неудач с адреса — без паузы, дальше 30·2^k с (не больше 900), окно 1 ч; удачный вход сбрасывает счёт |
| сессия | cookie `pcs_sid_<порт>; HttpOnly; SameSite=Strict`. Живёт 7 суток, без активности — 24 ч; смена пароля обнуляет все сессии |
| CSRF | `GET /api/session` → `{auth, user, csrf, version, port, fake}`. Каждый POST `/api/*` — с заголовком `X-CSRF: <csrf>` и своим (или пустым) Origin |
| CORS | нет. Чужие страницы сюда не ходят |
| выход | `POST /api/logout` |
| без сессии | `/api/*` → 401 `{"ok": false, "error": "нужен вход", "data": {"auth": false}}`; страницы → редирект на `/login` |
| журнал | каждый POST пишется в журнал панели (`journalctl -u pcs-web`) |

Пример с curl (на хосте):

```bash
J=/tmp/jar
curl -s -c $J -b $J -H 'X-CSRF: 1' -H 'Content-Type: application/json' \
     -d '{"user":"admin","password":"…"}' http://127.0.0.1:666/api/login
T=$(curl -s -b $J http://127.0.0.1:666/api/session | python3 -c 'import json,sys;print(json.load(sys.stdin)["data"]["csrf"])')
curl -s -b $J http://127.0.0.1:666/api/overview
curl -s -b $J -H "X-CSRF: $T" -H 'Content-Type: application/json' \
     -d '{"target":"2000","part":"proxyveth","args":["status"]}' http://127.0.0.1:666/api/run
```

### 13.3 Ответы

Всегда конверт `{"ok": true, "data": …}` или `{"ok": false, "error": "…"}`.

| HTTP-код | когда |
|---|---|
| 200 | запрос дошёл. Если действие не вышло (сервер недоступен, прокси упала) — 200 с `ok: false` |
| 400 | кривой запрос |
| 401 | нет входа |
| 403 | нет CSRF, чужой Origin или опасное действие без подтверждения |
| 404 / 405 | нет адреса / не тот метод |
| 500 | сбой панели — подробности в `journalctl -u pcs-web` |

Тело POST — JSON. Сводные ответы кэшируются на 4 с; действия, меняющие состояние, кэш сбрасывают.

### 13.5 Терминал (WebSocket)

- RFC 6455, версия 13, только с сессией и своим Origin.
- Не больше 24 терминалов сразу (иначе 503).
- Процесс — `api.term_argv(target)`: `ssh -tt root@сервер` ключом PCS или `bash -l` для хоста.

| направление | кадр |
|---|---|
| клиент → сервер | двоичный — ввод как есть; текстовый — JSON `{"type": "resize", "cols": C, "rows": R}` |
| сервер → клиент | двоичный — вывод pty |

Сервер закрывает соединение, когда процесс кончился; при закрытии вкладки процесс завершается.

### 13.6 Интерфейс

- **Каркас:** слева дерево, сверху «где я» (хост / ВМ / вкладка) и сводка (состояние,
  ВМ, модемы), дальше страница. На узком экране (< 900 px) дерево выезжает по кнопке ☰.
- **Дерево — вся система:** свой хост → его ВМ, затем «Присоединённые хосты» — каждый
  со своими ВМ (у Proxmox) и «+ Создать ВМ на …». Хост сворачивается (запоминается в
  браузере); поиск по номеру, имени, IP (клавиша `/`). У ВМ — цвет, точка состояния и шкала
  «работает модемов из скольких»; цвет — свой (один из 7) или по номеру. ВМ, которой нет в
  Proxmox, — красная, «нет в Proxmox».
- **Присоединённый хост выглядит как свой:** те же страницы по адресам `#/n/<имя>/…`
  (хост с вкладками, его ВМ со всеми вкладками, создание ВМ на нём, его задания). Запросы
  идут через хаб (`/api/nodes/<имя>/…` → его `/api/v1`), терминал — через хаб
  (`/ws/node/<имя>/term` → его `/api/v1/ws/term`; хаб только перекладывает кадры).
  Сверху — полоса: цвет хоста, «Его панель в новой вкладке», «Обновить PCS на нём», «Отсоединить».
- **Вкладки** хоста и ВМ: (обзор) / сетевые интерфейсы / modlink / терминал / управление /
  mp.space / ЮMoney. Старые ссылки `…/proxyveth` ведут на «сетевые интерфейсы».
- **Сетевые интерфейсы** — все модемы сервера в одном месте, без дублей:
  - **физические** (hivelink, USB) — N, интерфейс и USB-порт, связь, сеть и сигнал, данные,
    внешний IP («Проверить внешние IP»), заметки; в строке — «данные» (если выключены),
    «переподключить», «заново подключить USB». hivelink не стоит — строка с «Установить»;
  - **виртуальные** (proxyveth) — выключатель proxyveth (§8.3), источник, синхронизация,
    тесты, таблица, у каждого модема — поднять / остановить, пересоздать, диагностика, веб модема;
  - обычно на сервере что-то одно: раздел с модемами — сверху (физические первыми), пустой
    сжимается в строку внизу; есть и те и другие — сводка «N физических · M виртуальных».
- **Страница хоста** — вкладки обзор / сетевые интерфейсы / modlink / терминал / управление / mp.space / ЮMoney:
  - обзор: полоса показателей (ВМ работает, модемы, требуют внимания, настоящие модемы, ОЗУ);
    таблица ВМ (режим, модемы со шкалой, mp.space) с кнопками «Открыть», «Терминал» и «⋯»
    (включить, выключить, перезагрузить, стоп, «Убрать из PCS», «Удалить»); **«ВМ Proxmox не
    под PCS»** с кнопкой «Добавить в PCS» (IP и пароль root → задание: ключ хаба, код, части);
    фоновые задания;
  - настройка: разделы «Хост», «Доступ», «Сеть и софт», «Осторожно» (см. ниже).
- **Имя ВМ — из Proxmox:** переименовали ВМ там — PCS подхватит при следующем опросе.
- **Страница ВМ:** сверху шапка с цветной меткой выбранной ВМ, адресом, режимом, модемами и
  состоянием — перепутать сервер нельзя. Вкладки (бегунок под активной едет, а не прыгает):
  1. **сетевые интерфейсы** (физические — см. выше; виртуальные:) — режим, источник, время синхронизации; «Синхронизировать», «Тест ▾»
     (быстрый / с WAN IP), «Все модемы ▾» (up / down / restart), «Таблица ▾» (правка копии,
     источник); фильтры-счётчики (все / работают / ждут сервер / …); **у каждого модема —
     свои кнопки: ▶ поднять или ■ остановить, ↻ пересоздать, диагностика.** Столбец кнопок
     прибит к правому краю — виден, даже когда таблица шире экрана;
  2. **modlink** — §9.8;
  3. **терминал** — xterm.js (лежит в репозитории, MIT) и кнопки частых команд;
  4. **управление** — сведения о ВМ чипами, дальше разделы: «Машина» (питание,
     цвет, обновить агентов), «Доступ» (пароль root, ключ SSH), «Сеть и софт» (DNS,
     mp.space, hivelink), «Осторожно» (режим proxyveth, «Убрать из PCS»);
  5. **mp.space** и 6. **ЮMoney** — Яндекс Браузер на одно окно в своей сети через прокси (§13.8).
- **Новая ВМ:** форма по разделам (машина, режим — карточками, модемы), справа — «Что будет»:
  план задания под выбранные настройки (меняется на ходу). После «Создать» — страница задания.
- **Задание:** слева этапы (строки `── … ──` из журнала: пройденные — ✓, текущий — крутится,
  упавший — ✕), справа журнал целиком; часы — сколько идёт / за сколько сделано.
- **Присоединить хост:** форма слева, справа — как это работает и команда установки с кнопкой
  «скопировать».
- **Вход:** логин, пароль с кнопкой «показать», предупреждение о Caps Lock, понятная ошибка;
  после входа — на ту страницу, куда шли.
- Статика — чистые HTML/CSS/JS без сборки и без CDN; тёмная и светлая тема; шрифт Geist и
  Geist Mono (`static/fonts`, лицензия OFL); данные опрашиваются раз в ~10 с.
- **Движение** — только `transform` и `opacity`, 120–380 мс: страница и вкладка проявляются,
  строки входят лесенкой (шаг 26 мс), меню и окна раскрываются от кнопки, шкалы растут, числа
  досчитываются. При «уменьшить движение» в системе — без анимаций.

### 13.7 Быстрый вход: сначала запас, свежее — следом

Опрос всех ВМ долгий: ВМ с 40 модемами отвечает на `proxyveth status` 7–13 с, и раньше
экран после входа пустовал до ~20 с. Теперь:

- **Сервер** (`Panel.overview`): обзор моложе 8 с — как есть; старше — сразу прежний с
  `"stale": true, "age": N`, а свежий собирается в фоне (один сбор за раз). Удачный обзор
  пишется в `/var/lib/pcs/web-overview.json` (600) — после перезапуска панели первый ответ
  мгновенный, с диска. Любое действие (`forget`) — следующий обзор собирается сразу, без запаса.
- **Браузер:** последний обзор лежит в `localStorage` — дерево, шапка и обзор хоста рисуются
  до первого ответа; на месте того, чего ещё нет, — серые заготовки (скелеты); тонкая полоса
  сверху — идёт запрос. Пришёл `stale` — панель спросит ещё раз через 2,5 с.


### 13.8 Браузер вкладок mp.space и ЮMoney

Окно самого обычного браузера прямо в панели — с нужным адресом: mp.space нужен
европейский, ЮMoney — российский. Ничего не подделывается: браузер не знает ни о каком прокси,
он живёт в своей сети, где весь интернет — прокси пользователя, как компьютер за роутером
провайдера. Сверху — прокси, «Применить», «Проверить» и внешний адрес через прокси со страной и
часовым поясом (✓ «европейский адрес» / «российский адрес» или красное «нужен …»). Под ним —
кнопки-помогаторы (свои — карандашом: «Название | https://…»), дальше окно: «Вставить текст»
(буфер → браузер, дальше Ctrl+V), «Скопировать из браузера», во весь экран, «Закрыть браузер».

- **Браузер:** Яндекс Браузер для Linux — официальный пакет `yandex-browser-stable` из
  репозитория Яндекса (`repo.yandex.ru/yandex-browser/deb`; ключ ставится, только если отпечаток
  `224974DB7FED6DECB7D855EF60B9CD3A083A7A9A`). Обычный профиль и настройки; флаги — только те,
  что сайты не видят (профиль, без мастера первого запуска, пароли без связки ключей) и
  `--enable-unsafe-swiftshader`: штатный программный WebGL Chromium, как у любого Chrome без
  видеокарты (без него WebGL нет вовсе — это заметнее).
- **Сеть:** свой network namespace `pcsbr<N>` — в нём только `lo` и `tun0` sing-box,
  маршрут по умолчанию — в `tun0`. sing-box отдаёт всё пересыльщику на `127.0.0.1:1080` этого
  namespace; соединения к прокси пользователя (HTTP CONNECT или SOCKS5 с логином) пересыльщик
  открывает из сети машины. DNS перехватывается на tun и идёт через прокси по TCP; UDP прокси не
  возит — отклоняется сразу (браузер переходит с QUIC на TCP без ожиданий). WebRTC — как в сети с
  закрытым UDP: только кандидат `…local`, ни адреса машины, ни внутреннего адреса. Сеть машины
  не трогается: ни NAT, ни forwarding, ни правил маршрутизации; в `ss -tulpn` от браузера ничего.
- **Как обычный компьютер:** экран 1920×1080 (во вкладке — масштаб), шрифты DejaVu, Liberation,
  Noto, русский язык, часовой пояс — страны внешнего адреса прокси (меняется при следующем
  открытии). Видеокарты нет (WebGL — SwiftShader) — так у любого Chrome на ВМ и удалённом столе.
- **Сессии сохраняются:** профиль на (хост или ВМ, вкладка) — `/var/lib/pcs/browser/<ключ>/profile`
  (`2000-ym`, `host-mp`, `n-<хост>-2000-mp`): куки, вход, вкладки. «Закрыть браузер» закрывает
  окна как крестиком — вкладки и куки на месте при следующем открытии.
- **Сеанс** — юнит `pcs-browser-<ключ>` (systemd-run): root — namespace, пересыльщик,
  sing-box; от `pcs-browser` (без прав, `setpriv`) — dbus, Xtigervnc (VNC на unix-сокете),
  matchbox, браузер. Окно — noVNC 1.7.0 по WebSocket `/ws/browser?kind=mp|ym&target=…[&node=…]`.
  Запуск только по кнопке; никто не смотрит 30 мин — закрывается сам; не больше 4 разом.
- **Установка** — кнопка «Установить браузер» (задание, ≈500 МБ, Debian/Proxmox/Ubuntu amd64):
  репозиторий Яндекса, браузер, tigervnc, matchbox, шрифты, mesa, wmctrl, sing-box.
- **Проверено на стенде (18.10.2026):** yoomoney.ru, webglreport (WebGL — ANGLE/SwiftShader),
  1.1.1.1 открываются через прокси; тест WebRTC (webrtc.github.io, trickle ICE) — только
  `…local`; закрыть/открыть — все вкладки на месте. Через российский выход стенда часть сайтов
  проверки утечек (browserleaks, ipleak) не открывается — TLS обрывается снаружи, это блокировка
  по пути, не браузер. mobileproxy.space из России отдаёт адрес-заглушку — для него нужен
  европейский прокси.
- **ЮMoney:** новый «компьютер» и IP — почти наверняка подтверждение входа кодом. Важнее всего
  IP: российский, без смены посреди работы (модем без автореконнекта), не входить одновременно
  из разных мест.
- **Дальше (не сделано):** аналитика mp.space по API раз в сутки через этот же прокси.

### 13.9 Веб модемов в отдельном окне (с 23.10.2026)

На Windows веб модема открывался прямо на компьютере с модемами. Здесь модемы — на хосте или в ВМ,
поэтому 🔗 «веб модема» в строке (сетевые интерфейсы: настоящие модемы hivelink и виртуальные
proxyveth; modlink) открывает **новое окно браузера** на компьютере пользователя: в нём — браузер
модемов этой машины, вкладка `http://192.168.N.1/`. Одно окно на машину (`#/md/<id>`), каждый
следующий модем — новая вкладка в нём; вход в веб модемов сохраняется (профиль `<id>-md`).
У виртуального модема proxyveth это веб настоящего модема за прокси (через посредника
`192.168.N.1` на сервере, опасные записи им не пропускаются, §8.5).

- Тот же Яндекс Браузер и та же схема, что у вкладок §13.8 (namespace, sing-box, noVNC), но вместо
  прокси пользователя пересыльщик ходит к модемам машины: хост — прямо с хаба, ВМ — через SSH хаба
  (`ssh -W 192.168.N.1:80`, свой мастер-канал в каталоге сеанса).
- Пускает только TCP к частным адресам (192.168/16, 10/8, 172.16/12) на портах 80, 443, 8080,
  8443 — и в sing-box, и в пересыльщике; DNS и всё прочее браузеру модемов отклоняется сразу.
- Окно не открылось — браузер пользователя заблокировал всплывающее окно: разрешить для панели.
  Присоединённый хост — веб его модемов в его собственной панели.
- Проверено на стенде: браузер модемов ВМ 2000 — вкладки 192.168.101.1 (посредник proxyveth) и
  192.168.88.1 (роутер стенда) через туннель SSH; журнал сеанса чистый.

## 14. API хаба (Python, `pcs/hub/api.py`)

Панель — тонкий слой над этими функциями. Ошибки — `pcs.core.util.Fail` (текст для
человека). Долгое — фоновым заданием: функция сразу отдаёт `job_id`.

```python
host_info()                      # {"name", "kind": "proxmox", "version", "cpu", "ram", "disk", "hivelink": {…}}
servers()                        # [{"id", "name", "ip", "state", "mode", "modems": {"ok","warn","broken","total"}, "mpspace"}]
server(id)                       # то же + версии частей
create_server(params) -> job_id  # params: name, cores, ram_gb, disk_gb, mode, sheet, mpspace
delete_server(id, confirm)       # confirm == id
run(id, part, args, timeout=300, input=None) -> конверт   # id=None — хост (hivelink, modlink); input — stdin
dns_fix(target, dns=None)        # target: id или "host"
set_password(target, password)
set_key(target, pubkey=None, rotate=False)
mpspace(target, action, **kw) -> job_id | dict
update(target=None) -> job_id | dict
job(job_id)                      # {"id", "kind", "title", "state": running|done|failed, "started", "finished", "log": […], "result", "error"}
term_argv(target) -> list        # argv для pty терминала
```

**Значения:**

| поле | значения |
|---|---|
| `servers()[i]["state"]` | `running`, `stopped`, `paused`, `absent` (ВМ нет в Proxmox), `offline` (ВМ работает, SSH не отвечает), `old` (нет `pcs-node` — нужен `pcs update`) |
| `mode` | `"usb"`, `"gw"`, `None` |
| `mpspace` | `None` (не спрашивали) или `{"installed", "ok", "units": {юнит: состояние}, "port", "auth"}` |

**Задания.** Отдельный процесс `pcs job run ID` в юните `pcs-job-ID` — переживает
перезапуск панели и обрыв браузера. В `/var/lib/pcs/jobs/`:
- `ID.json` — состояние;
- `ID.log` — всё, что задание напечатало;
- `ID.params` (600) — параметры, удаляется, как только задание их прочло.

Хранятся последние 50.

## 16. Безопасность

- **Секреты** (пароли прокси, auth.mp, пароль панели, ключи):
  - в файлах 600, каталоги 700;
  - на сервер идут через stdin, а не в командной строке (`ps` их не видит);
  - пароль root при создании ВМ — хэшем в cloud-init.
- **Панель:**
  - без CORS, CSRF на каждом POST, `SameSite=Strict`, пауза после неудачных входов;
  - опасное — с подтверждением номером;
  - HTTP без TLS: порт открывается пользователем на время работы.
- **modlink:**
  - субпроцессы только списком аргументов, без `shell=True`. В старом modlink пароль из
    панели попадал в shell — выполнение команд от root;
  - через прокси закрыты локальная сеть сервера и IPv6;
  - пароли в API — только по явному запросу (`reveal`, `export`).
- **Веб-морда модема** режет опасные записи HiLink; SMS открыты сознательно.
- **Чужое не трогаем:**
  - `/usr/local/bin/sing-box`;
  - правила и таблицы других частей и mp.space;
  - порт 5000 старого modlink;
  - устройства на `dummy_hcd` (для hivelink).

## 17. Грабли, которые PCS обходит сам (история решений)

0. **Создание ВМ падало «нет SSH до сервера»** (12.10, ВМ 2000 MskAn3):
   - ожидание cloud-init было одним многоминутным SSH-соединением, а cloud-init
     перенастраивает сеть — соединение рвалось;
   - после перезагрузки (mp.space) хаб считал сервер поднятым после первого удачного захода,
     а сеть ещё перестраивалась, и общее SSH-соединение (ControlMaster) зависало:
     «Failed to connect to new control master».

   Теперь:
   - cloud-init ждём короткими опросами; если адрес по DHCP сменился, перечитываем его;
   - после загрузки ждём три удачных SSH подряд;
   - шаги после перезагрузки повторяются при обрыве;
   - зависшее общее соединение закрывается (`ssh -O exit`).

1. **Отдельная ВМ на каждый модем не нужна.** Модем — netns плюс USB-гаджет на `dummy_hcd`.
   40 модемов поднимаются меньше чем за минуту на одной ВМ.
2. **У каждого модема своя USB-шина, а шин не больше 63.** Отсюда предел режима usb
   (~40–55). Пустые слоты шину не держат.
3. **У всех E3372h один MAC.** Имя `enx…` достаётся только первому, на остальных udev
   падает. `.link` с `NamePolicy=` оставляет `ethN`, как у mp.space.
4. **systemd-networkd при перезапуске стирает чужие `ip rule`** (любой `netplan apply`) →
   drop-in §11.2; пропавшее правило `sync` замечает и чинит.
5. **dnsmasq иногда не подхватывает интерфейс модема** — проверяется и перезапускается;
   mp.space повторять DHCP не умеет.
6. **Падение туннеля стирает его маршруты** — их ставит `ExecStartPost` при каждом старте sing-box.
7. **Выгрузка `dummy_hcd` при живом гаджете ломает ядро** — разборка всегда сверху вниз;
   не привязавшийся слот обходится.
8. **UDP через прокси ген1 не работает**: UDP ASSOCIATE принимается, но порт ретранслятора
   на стороне прокси закрыт. Поэтому DNS — по TCP. В режиме gw остальной UDP режется сразу.
9. **veth `vxN` на сервере агрегатора были лишними** (PCS 4.1, PR #2). sing-box ушёл в
   netns, выход к прокси — через сокет systemd в netns и `systemd-socket-proxyd` на сервере.
10. **Вариант «sing-box со стеком gvisor на сервере, tun перенесён в netns» ронял ядро 6.8** —
    гонка в `u_ether` (`eth_start_xmit`), 2 падения из 2. Остались на стеке `system`.
    Страховка — `kernel.panic=10`.
11. **udhcpc ставит маршрут через модем с метрикой 0** → петля соединений к прокси (§11.3).
12. **sing-box прописывал DNS своего tun в resolved чужого интерфейса** через D-Bus → D-Bus
    закрыт (§11.5).
13. **Разные версии sing-box в `/usr/local/bin`** ломали друг друга → свой путь и одна версия 1.14.2.
14. **«QEMU Tablet» в `lsusb` выдаёт виртуалку** → `tablet 0`.
15. **sshd в образе Ubuntu** берёт первое значение из `sshd_config.d`, а образ кладёт
    `60-cloudimg` → свой файл `10-pcs.conf`.
16. **Порт SSH на 24.04** задаётся через `ssh.socket`, а не `sshd_config`.
17. **mp.space занимает порт 10000** на сервере → modlink по `auto` берёт следующий свободный.
18. **Паника ядра в `u_ether` при вынимании гаджета** (ВМ 1000, ядро 6.8.0-142, 13 падений с
    13.10 по 22.10, все — `eth_start_xmit`, `list_del` по `LIST_POISON1`): пакет (UDP sing-box,
    dnsmasq, ARP ядра) входит в передачу `usb0` одновременно с отключением функции ECM. При
    proxyveth гаджет вынимается намного чаще, чем при vmodem (перезагрузка модема, replug,
    лечение sync). Защита (PCS 5, 22.10): перед любым выниманием — `usb0` down в netns модема
    (опущенный интерфейс ядро драйверу не передаёт), после вставки — up и маршрут в таблице
    100. Так в `reboot_cycle`, `replug` (обе стороны) и `destroy`. На тестовой ВМ 2000
    гонку искусственно не воспроизвели: без защиты 3469 replug и 6296 циклов «вынуть/вставить»
    под потоком UDP — ни одной паники; с защитой 6446 циклов — тоже, модемы после этого в
    порядке. Подтвердит только рабочая ВМ после обновления.
19. **После перезагрузки хоста у ВМ сменился ключ SSH** (ВМ 1000, 23.10): Proxmox собирает
    instance-id cloud-init из user-data и сетевых настроек ВМ, а в них — поиск DNS хоста (если у
    ВМ свой не задан). Данные поменялись — cloud-init считает ВМ новой машиной: новые ключи SSH,
    заново user-data (пароль root из создания, `apt upgrade`, пакеты, `runcmd`). Хаб видел «Host
    key verification failed», панель — «нет SSH». Теперь: ключ сверяется через guest agent и
    принимается сам (§6, хранилище хаба), а cloud-init у ВМ PCS после создания выключен.
20. **Реконнект mp.space «не работал», хотя IP менялся** (serverspb, ВМ 3000, 40 модемов
    Huawei, 24.10). Облако mp.space отвечало `523 Bad request to equipment`, в журнале
    сервера — `ChangeIP ERR IP` через 49 с.
    - Запись трафика показала: команды модему (данные выкл., смена режима сети, данные вкл.)
      проходят за секунду, модем на всё отвечает OK и получает новый IP.
    - Ломалась проверка IP. Перед ней mp.space ищет рабочий сайт проверки
      (checkip.amazonaws.com и др.) и ждёт ответа не дольше 5 с. А имена искались 3–20 с.
    - У провайдера serverspb запросы к 1.1.1.1 и 8.8.8.8 по UDP теряются в 40–50 % случаев
      (по TCP проходят; 9.9.9.9, Яндекс и роутер отвечают всегда). `pcs dns` ставил именно
      1.1.1.1 и 8.8.8.8.
    - На Windows 10 DNS берётся от роутера, поэтому там всё работало.

    Теперь `pcs dns` проверяет серверы и заменяет теряющие (§11.4). После этого все
    реконнекты прошли штатно за 2–4,5 с, а имена ищутся за ~20 мс.

## 19. Связь хостов (с 12.10.2026)

Хосты PCS — Proxmox (с ВМ) и Ubuntu-VPS (модемы прямо на нём) — связываются по API.
Один хост (обычно Proxmox, где ты работаешь) — **хаб**: он видит присоединённые хосты,
их состояние, открывает их панели и управляет ими.

### Как присоединить VPS

1. Арендовать VPS с Ubuntu 24.04, поставить PCS: `bash <(curl -fsSL …/install.sh)` —
   спросит логин и пароль панели, режим proxyveth (`usb` для mp.space) и mp.space.
2. Открыть её панель `http://IP:666`: модемы во вкладке proxyveth, mp.space — в
   «настройке и управлении». Там же, в «Связь хостов», — **отпечаток** её сертификата.
3. На хосте Proxmox: в дереве «+ Присоединить хост» → адрес VPS, логин и пароль её
   панели (по желанию — отпечаток из п. 2). Или в терминале:
   `pcs node add IP --user admin --fingerprint AB:CD:…` (пароль — вопросом или
   `PCS_NODE_PASSWORD`).
4. VPS появилась в дереве в разделе «Присоединённые хосты»: модемы, режим, mp.space,
   версия PCS. Кнопки: **«Открыть панель хоста»** (вход без пароля, одноразовая ссылка
   на 60 с), «Обновить PCS на нём», «Отсоединить».

Порт один — **666**: тот же, что у панели. Открыть его на VPS (у хостера, ufw).

### Как устроено

- **HTTPS на том же порту.** Панель различает HTTP и TLS по первому байту соединения:
  браузер открывает `http://IP:666`, хосты между собой — `https://IP:666`. Сертификат
  свой, создаётся при первом запуске панели: RSA 2048, 10 лет, `/etc/pcs/tls/` (ключ 600).
  Отпечаток (SHA-256) — `pcs web status`, панель → настройка хоста → «Связь хостов».
- **Отпечаток запоминается при присоединении** (TOFU; если его ввели — сверяется сразу).
  Дальше хаб сверяет его **до отправки токена**: другой сертификат на том же адресе —
  отказ «это может быть подмена».
- **Логин и пароль нужны один раз.** `POST /api/v1/join` (только по HTTPS) проверяет их
  как вход в панель (с той же паузой после неудач) и выдаёт **токен**; пароль нигде не
  хранится. У хаба — `/etc/pcs/nodes/<имя>.json` (600: адрес, порт, отпечаток, токен);
  у VPS — только SHA-256 токена в `/etc/pcs/tokens.json` (`pcs token list`, `revoke`).
- **`/api/v1/<путь>`** с `Authorization: Bearer …` — те же адреса, что `/api/<путь>` у
  браузера (§13.4), тот же конверт. Только по HTTPS; запрос с заголовком `Origin`
  (страница в браузере) — отказ. Плюс: `POST /api/v1/login-link` (одноразовая ссылка
  входа, 60 с), `POST /api/v1/leave` (отозвать свой токен — так отсоединяется хаб).
- **Хаб проксирует**: `/api/nodes/<имя>/<путь>` → `/api/v1/<путь>` того хоста.
  Долгие команды там — задания того хоста; хаб показывает их журнал.
- **Терминал** (`pcs node …`):
  - `pcs node [list]` — список и состояние;
  - `pcs node add|remove|open`;
  - `pcs node ИМЯ status`;
  - `pcs node ИМЯ proxyveth|modlink|hivelink …` — команда части там. Долгая идёт заданием
    там же, журнал печатается здесь;
  - `pcs node ИМЯ job [ID]`.
- Сводка присоединённых хостов опрашивается параллельно, с таймаутом. Недоступный —
  «нет связи» с причиной, а не падение всей панели.

**Проверено 12.10.2026 на стенде:**
- ВМ 4000 (чистая Ubuntu 24.04.5) с PCS как VPS присоединена к хосту `servervolga`;
- неверный пароль и чужой отпечаток — отказ;
- `pcs node list` — «модемы 1/1»;
- `pcs node vps-test proxyveth status` и `… sync` (заданием там);
- одноразовая ссылка пускает один раз;
- на VPS `pcs token list` — «хаб servervolga».
- Автотесты: `tests/test_nodes.py` — настоящий TLS, присоединение, вызовы, задания,
  подмена сертификата, чужой токен, отсоединение.

**С 12.10 (вечер) — единая система:** страницы присоединённого хоста и его ВМ — прямо в
